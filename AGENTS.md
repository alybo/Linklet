# Linklet: правила работы с GitHub и релизами

## Обычные задачи

- Все сборки приложения называть `Linklet.app`, чтобы владелец мог заменять их
  при тестировании. Версию указывать в имени каталога или архива, а не `.app`.
- Сначала собрать и проверить изменения локально. Передать владельцу `Linklet.app`
  для тестирования версии. До подтверждения результатов и явной команды владельца
  вся работа остаётся локальной, включая коммиты.
- Перед коммитом выполнить `git status` и добавить только файлы текущей задачи.
  Чужие, диагностические и непонятные изменения не включать; показать их владельцу.
- Запускать только тесты затронутой части. Для Swift выбирать нужные классы или
  методы через `-only-testing:LinkletTests/Класс/метод` в `xcodebuild test`
  проекта `Linklet/Linklet.xcodeproj`, схемы `Linklet`, SDK `macosx`, с
  `CODE_SIGNING_ALLOWED=NO`. Полный прогон тестов приложения запускать только
  по явной просьбе владельца, в том числе при запуске через скрипт.
- После изменения Raycast запускать из `integrations/raycast-linklet`: `npm test`,
  `npm run typecheck`, `npm run build`, `npm run lint:source`.

## Версии и релизы

- После локальной проверки и по явной команде владельца отправить согласованный
  код версии в `origin/main` и подготовить черновик GitHub Release для коллеги.
  До передачи черновика в `main` должны быть код версии, `MARKETING_VERSION`,
  возрастающий `CURRENT_PROJECT_VERSION` и заметки версии. Тег `vVERSION`
  должен указывать на этот коммит.
- В черновик загрузить ZIP с `Linklet.app` без подписи Developer ID и
  нотарификации. Коллега заменяет временный ZIP готовыми артефактами при выпуске.
- За подпись, нотарификацию и публичный выпуск отвечает коллега с правами GitHub
  и Apple Developer ID. Он самостоятельно выполняет
  `scripts/release-preflight.sh`, затем `scripts/publish-release.sh`. Скрипт
  подписывает, нотарифицирует, публикует ровно два Assets и обновляет appcast
  последним. После подписи ничего возвращать владельцу для публикации не нужно.
- Не создавать и не менять вручную сертификаты, закрытые ключи, токены или
  provisioning profiles. Полный процесс: `RELEASING.md` и
  `Linklet/docs/SIGNING-HANDOFF.md`.

## Продуктовые границы

- Linklet принимает для предпросмотра только HTTP(S)-ссылки и отправляет в
  выбранный браузер исходный входящий URL, а не состояние WebKit-вкладки.
- Приватное хранение данных сайтов — значение по умолчанию; постоянные данные
  включаются только явным выбором пользователя.
- Тяжёлую и сетевую работу не выполнять на MainActor.
