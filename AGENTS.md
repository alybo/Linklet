# Linklet: правила работы с GitHub и релизами

## Обычные задачи

- Каждая завершённая пользовательская функция должна быть проверена, закоммичена и
  отправлена в `origin/main`, если пользователь явно не просит оставить её локально.
- Перед коммитом выполнить `git status` и добавить только файлы текущей задачи.
  Чужие, диагностические и непонятные изменения не включать; показать их владельцу.
- После изменения Swift-кода запускать:
  `xcodebuild -project Linklet/Linklet.xcodeproj -scheme Linklet -sdk macosx test CODE_SIGNING_ALLOWED=NO`.
- После изменения Raycast запускать из `integrations/raycast-linklet`: `npm test`,
  `npm run typecheck`, `npm run build`, `npm run lint:source`.

## Версии и релизы

- Обычный push не создаёт релиз. Тег и выпуск создаются только по явной задаче
  владельца после завершения плана версии.
- Перед выпуском код версии, `MARKETING_VERSION`, возрастающий
  `CURRENT_PROJECT_VERSION`, заметки версии и тег `vVERSION` должны быть в `main`.
- Компаньон с правами GitHub и Apple Developer ID самостоятельно выполняет
  `scripts/release-preflight.sh`, затем `scripts/publish-release.sh`. Скрипт
  подписывает, нотарифицирует, публикует ровно два Assets и обновляет appcast
  последним. После подписи ничего возвращать владельцу для публикации не нужно.
- Не создавать и не менять вручную сертификаты, закрытые ключи, токены или
  provisioning profiles. Полный процесс: `RELEASING.md` и
  `Linklet/docs/SIGNING-HANDOFF.md`.

## Продуктовые границы

- Linklet принимает для предпросмотра только HTTP(S)-ссылки и отправляет в
  выбранный браузер исходный входящий URL, а не состояние WebKit-вкладки.
- Приватное хранение данных сайтов — значение по умолчанию; постоянные данные
  включаются только явным выбором пользователя.
- Тяжёлую и сетевую работу не выполнять на MainActor.
