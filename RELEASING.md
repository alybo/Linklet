# Выпуск Linklet

Публичные исходники и готовые выпуски: https://github.com/alybo/Linklet.
Совместная разработка ведётся в том же публичном репозитории. Linklet-dev больше не используется для текущей работы.

## Текущая подготовка

Следующий выпуск — **1.2, сборка 3**. Видимые версии теперь состоят из двух частей;
внутренний номер сборки увеличивается независимо. Тег 0.1.1 содержит сборку 2.
Версию и номер сборки всегда сохранять в проекте Xcode до создания тега.
Подробная передача для подписи: [Linklet 1.2](Linklet/docs/RELEASE-1.2.md).

## Что получает пользователь

В GitHub Releases для каждой версии загружаются ровно два файла:

- `Linklet-VERSION.dmg` — подписанный и нотарифицированный образ с приложением; его же использует Sparkle.
- `Linklet-VERSION-source.tar.gz` — соответствующие исходники этой сборки, включая необходимые сторонние зависимости и инструкции сборки.

В описании релиза: «Для установки скачайте DMG», изменения, требования macOS,
ссылка на исходники и контрольные суммы обоих файлов. Отдельные ZIP приложения,
SHA256SUMS.txt, appcast.xml и release-description.md в Assets не загружать.
Автоматические ссылки Source code (zip / tar.gz) GitHub добавляет сам.

Автоматический архив Source code от GitHub не включает скачиваемые Swift-пакеты. Он не заменяет полный архив соответствующих исходников.

## Порядок выпуска

1. Установить версию и возрастающий номер сборки; проверить тесты.
2. Опубликовать согласованный исходный код под GPL-3.0-only, сохранить сторонние лицензии и установить тег версии. Не включать ключи, сертификаты и личные настройки.
3. Компаньон собирает именно этот код, подписывает Developer ID Application, выполняет notarization и stapling. Подробности — в Linklet/docs/SIGNING-HANDOFF.md.
4. Подготовить соответствующие исходники: код приложения, файлы проекта, ресурсы, необходимые скрипты сборки и точные версии зависимостей из Package.resolved вместе с их лицензиями. Проверить, что архив позволяет собрать эту версию; документировать настройку локальных зависимостей. Проверить также транзитивные зависимости. Не включать ключи подписи издателя.
5. Создать DMG с нотарифицированным приложением и ссылкой на /Applications; подписать и нотарифицировать сам DMG, прикрепить ticket. Запустить scripts/prepare-sparkle-update.sh с финальным DMG, полным архивом исходников и путём к инструментам Sparkle. Скрипт проверит образ и приложение, подпишет образ для Sparkle и подготовит каталог release/ с двумя файлами, feed/appcast.xml и текст release-description.md отдельно.
6. Проверить установку и реальное обновление с предыдущей сборки. Создать черновик Release с двумя файлами из release/ и описанием. Опубликовать их одновременно, проверить скачивание, затем опубликовать appcast последним. Не менять подписанный DMG. Хранить исходники доступными всё время распространения бинарника.

Sparkle и GitHub Pages уже работают для 0.1.1. Сохранять существующий ключ
издателя, bundle identifier и Team. Новую запись в ленту добавлять только после
публикации соответствующего подписанного выпуска.
Порядок настройки и выпуска обновлений: [Обновления Linklet](Linklet/docs/UPDATES.md).
Готовый текст задания: [Промпт для нейронки компаньона](Linklet/docs/RELEASE-AGENT-PROMPT.md).
