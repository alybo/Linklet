# Выпуск Linklet

Публичные исходники и готовые выпуски: https://github.com/alybo/Linklet.
Совместная разработка ведётся в том же публичном репозитории. Linklet-dev больше не используется для текущей работы.

## Быстрый путь

Начиная со следующей версии выпуск выполняется двумя командами. Дорогие проверки
делаются заранее один раз для неизменяемого тега, а публикация использует их
проверенную квитанцию и обычно не повторяет тесты:

```sh
scripts/release-preflight.sh
scripts/publish-release.sh
```

До preflight нужно сохранить новую `MARKETING_VERSION` и возрастающий
`CURRENT_PROJECT_VERSION`, закоммитить изменения, создать и отправить тег
`vVERSION`, причём `origin/main`, тег и локальный `HEAD` должны указывать на один
коммит. Повторный запуск preflight на том же коммите мгновенно переиспользует
квитанцию; `--force` запускает проверки заново, сохраняя кэш Xcode/SwiftPM.

`publish-release.sh` — единственная команда публикации. Она собирает universal
архив, подписывает Developer ID, напрямую отправляет приложение и DMG через
`notarytool`, прикрепляет tickets, создаёт Sparkle-ленту, публикует ровно два
файла релиза, сверяет повторно скачанные байты и только затем обновляет Pages.
При прерванном запуске продолжать через `scripts/publish-release.sh --resume`:
скрипт проверяет готовые этапы перед повторным использованием.

По умолчанию используется профиль `scribe-notary`. Это имя профиля Связки
ключей, а не имя приложения, поэтому отдельный профиль `Linklet` не нужен.
Один раз на новом Mac профиль создаётся интерактивно:

```sh
xcrun notarytool store-credentials scribe-notary
```

Имя можно переопределить через `LINKLET_NOTARY_PROFILE`; сертификат и Team —
через `LINKLET_SIGNING_IDENTITY` и `LINKLET_DEVELOPMENT_TEAM`. Пароли, API-ключи
и сертификаты в репозиторий или аргументы команды не записывать. Проверить план
без сборки и внешних изменений можно через `--dry-run` у обеих команд.

## Что получает пользователь

В GitHub Releases для каждой версии загружаются ровно два файла:

- `Linklet-VERSION.dmg` — подписанный и нотарифицированный образ с приложением; его же использует Sparkle.
- `Linklet-VERSION-source.tar.gz` — соответствующие исходники этой сборки, включая необходимые сторонние зависимости и инструкции сборки.

В описании релиза: «Для установки скачайте DMG», изменения, требования macOS,
ссылка на исходники и контрольные суммы обоих файлов. Отдельные ZIP приложения,
SHA256SUMS.txt, appcast.xml и release-description.md в Assets не загружать.
Автоматические ссылки Source code (zip / tar.gz) GitHub добавляет сам.

Автоматический архив Source code от GitHub не включает скачиваемые Swift-пакеты. Он не заменяет полный архив соответствующих исходников.

## Что входит в preflight

Preflight проверяет соответствие тега, коммита, версии и номера сборки; запускает
Python-, Xcode- и Raycast-тесты; собирает полный corresponding-source архив с
точными SwiftPM-зависимостями и лицензиями; затем действительно собирает проект
из локальных копий зависимостей. Квитанция содержит коммит и SHA-256 архива.
Публикация остановится, если изменился коммит, тег, версия, build, результат
проверки или хотя бы один байт архива исходников.

Настоящее обновление предыдущая → новая версия не нужно вручную повторять в
каждом патч-релизе. Его обязательно повторять, если менялись Sparkle, `SUFeedURL`,
ключ обновлений, логика `AppUpdateService`, формат appcast/подписи или сам процесс
установки; также перед первым выпуском новой major/minor-линии. Обычный выпуск
всегда проверяет подпись Sparkle, URL и размер enclosure, подписи Apple, tickets,
Gatekeeper, состав DMG, публичные байты и публичную ленту.

Sparkle и GitHub Pages уже работают для 0.1.1. Сохранять существующий ключ
издателя, bundle identifier и Team. Новую запись в ленту добавлять только после
публикации соответствующего подписанного выпуска.
Низкоуровневый `scripts/prepare-sparkle-update.sh` остаётся внутренним шагом и
полезен для диагностики, но для обычного релиза вручную его запускать не нужно.
Дополнительные сведения: [Обновления Linklet](Linklet/docs/UPDATES.md) и
[Подпись](Linklet/docs/SIGNING-HANDOFF.md).
