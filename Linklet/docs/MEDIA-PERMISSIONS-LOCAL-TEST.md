# Нативные разрешения камеры и микрофона

30 октября 2026. Локальная сборка, без публикации и изменения версии.

## Интерфейс macOS 27

Запрос сайта — стандартный AppKit `NSAlert`, прикреплённый к его окну. Кнопки, checkbox запоминания, размеры, фон и анимации рисует macOS. В настройках сайтов используется существующий SwiftUI grouped Form со стандартными Section, DisclosureGroup и Picker. Собственных стеклянных слоёв, палитры и геометрии диалога нет.

Сборка использует SDK macOS 27.0; проверяемая система — macOS 27.2. Стандартные компоненты получают актуальный вид системы согласно [рекомендациям Apple по macOS 27](https://developer.apple.com/videos/play/wwdc2026/289/). Минимальная поддерживаемая версия остаётся macOS 14; на ней будет её собственное нативное оформление.

## Два уровня согласия

1. WebKit передаёт запрос через публичный [WKUIDelegate.requestMediaCapturePermissionFor](https://developer.apple.com/documentation/webkit/wkuidelegate/webview(_:requestmediacapturepermissionfor:initiatedbyframe:type:decisionhandler:)). Нативный диалог Linklet показывает фактический origin и запрошенные устройства. Для iframe отдельно указан сайт, в который он встроен. Камера + микрофон в одном getUserMedia дают один запрос сайта.
2. Только после «Разрешить» запрашивается доступ самого приложения через публичный [AVCaptureDevice.requestAccess](https://developer.apple.com/documentation/avfoundation/avcapturedevice/requestaccess(for:completionhandler:)). Системный TCC-диалог полностью принадлежит macOS. При уже выданном разрешении он не повторяется; при системном запрете сайт получает отказ и нативное сообщение с переходом в настройки конфиденциальности.

Приложение не запрашивает устройства при запуске или открытии настроек. AVFoundation используется для статуса/согласия, запись и устройства принадлежат WebKit: Linklet не создаёт AVCaptureSession и не получает аудио/видеоданные.

Info.plist содержит обе usage description с русской и английской локализациями. Для Hardened Runtime добавлены camera/audio-input entitlements в Debug и отдельный Release entitlement-файл. Сертификаты, ключи и provisioning profiles не изменялись.

## Правила сайтов и приватность

- Раздельные состояния камеры и микрофона: «Спрашивать», «Разрешить», «Запретить». Запоминание в диалоге по умолчанию выключено; без него согласие не становится постоянным правилом.
- Ключ правила — два origin: верхний сайт и инициатор запроса. Учитываются схема, hostname и порт. Разрешение iframe на одном сайте не переносится на другой верхний сайт. Обрабатываются HTTPS и доверенный HTTP loopback; обычный HTTP, opaque/невалидные origin и отсоединённые страницы получают отказ.
- В приватном режиме правила живут только в памяти и удаляются при закрытии последнего окна сайтов. На диск они попадают только при явно включённом сохранении данных сайтов. Выключение сохранения/удаление данных удаляет соответствующие разрешения.
- Запрет останавливает выбранный вид текущего захвата через публичные setCameraCaptureState/setMicrophoneCaptureState(.none). Микрофон не останавливается из-за отдельного запрета камеры. «Сбросить» отзывает и разовые разрешения. При необходимости повторного запроса сайт можно обновить.
- WebKit управляет захватом на уровне WKWebView; отзыв разрешения встроенного origin может остановить соответствующее устройство для всего окна, а не только одного iframe.
- Переходы, закрытие и сбой процесса завершают ожидающие решения отказом ровно один раз. Поздний ответ сайта/TCC не выдаёт доступ следующему документу. Одновременные независимые запросы камеры и микрофона не отменяют друг друга.
- Во время согласия, переключения в системные настройки и активного захвата выключено старое автоматическое закрытие предпросмотра при деактивации приложения. Явное закрытие/выход останавливают захват; обычная настройка видимости окон продолжает действовать.

Демонстрация экрана и геолокация в эту задачу не входят.

## Проверки

Обязательный полный прогон:

```sh
xcodebuild -project Linklet/Linklet.xcodeproj -scheme Linklet -sdk macosx test CODE_SIGNING_ALLOWED=NO
```

**6 новых тестов, 0 ошибок**, TEST SUCCEEDED. Лог: `/tmp/linklet-media-permissions-final-feature-tests.log`.

**19 связанных тестов SiteDataTests, LocalizationTests и URLPolicyTests, 0 ошибок**, TEST SUCCEEDED. Лог: `/tmp/linklet-media-related-tests.log`. Итого подтверждены 25 проверок, непосредственно связанных с изменением.

Полный прогон столкнулся с блокировкой экрана (`CGSSessionScreenIsLocked = 1`, frontmost application = loginwindow), из-за чего уже существующие клавиатурные UI-тесты не смогли получить фокус; не завершена и проверка геометрии анимированной подсветки на активном экране. Попытка отдельного bundle ID не решает блокировку графической сессии. Это не считается успешным полным прогоном. Пользователю предложено разблокировать экран; все новые и перечисленные выше связанные проверки выполнены успешно с обычным Bundle ID.

Шесть новых SiteMediaPermissionTests проверяют:

1. Независимость одновременных запросов камеры/микрофона и отсутствие автоматического постоянного согласия.
2. Раздельные временные решения и очистку при последнем закрытии.
3. Отмену нативного и ожидающего системного ответа при навигации/закрытии, без позднего grant.
4. Пары origin, persistent/private режим, отказ macOS, отсутствие повторного TCC-запроса после запрета, удаление правил.
5. Настоящий WKUIDelegate и getUserMedia на синтетических устройствах WebKit, один объединённый consent, отзыв видео с сохранением аудио, полный сброс. Mock capture включается до создания WKWebView; при отсутствии тестового API тест пропускается без обращения к физическим устройствам. Ослабление требования фокуса действует только в этом тесте, не в приложении.
6. Настоящий нативный NSAlert sheet с последующим отказом, без запуска захвата.

Настоящие камера/микрофон и реальные TCC-разрешения в автоматических тестах не включались и не менялись. Их нужно проверить владельцу в подготовленной app. Минимальная macOS 14 и Developer ID Release отдельно не проверялись.

## Ручная проверка

1. Полностью завершить старый Linklet и запустить новую сборку. Открыть доверенный HTTPS-сайт для звонков/проверки устройств и запросить камеру/микрофон.
2. Проверить нативный запрос с адресом сайта, отказ, разовое согласие и checkbox запоминания. При первом согласии macOS отдельно запросит доступ Linklet.
3. В настройках → «Данные сайтов» → «Камера и микрофон» проверить системный статус и отдельные правила. Запретить камеру во время тестового захвата: видео остановится, микрофон продолжит работу; затем запретить микрофон.
4. При системном запрете открыть системные настройки соответствующей кнопкой, разрешить доступ и повторить запрос на сайте. Во время этого перехода окно не должно закрываться.
5. Проверить обычное и открытое сайтом окно, навигацию/закрытие во время запроса, приватное закрытие всех окон, сохранение только при включённом хранении данных.
