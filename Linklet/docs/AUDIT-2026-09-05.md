# Аудит Linklet 0.1.0 — 5 сентября 2026

Проверен исходный проект в PeekRoute-0.1.0-source: интерфейс, настройки, состояние приложения, WebKit, обнаружение и запуск браузеров, конфигурация проекта, документация и существующие тесты. Код приложения не изменялся.

**Вывод:** основа компактного предпросмотра разумная, но настройки пока требуют понимания внутренней логики приложения. Экспертная оценка понятности настроек — **5/10**, первого запуска — **3/10**. Это эвристическая оценка, а не результат пользовательского исследования. Оценку визуальной отделки в баллах не выставляю без просмотра актуального окна.

## Приоритетные находки

### 1. P1 — тупик после скрытия всех браузеров

**Подтверждено кодом.** В настройках можно выключить все цели. Когда список видимых целей пуст, предпросмотр показывает Choose browsers, но обработчик вызывает только refreshTargets. Этот метод не снимает скрытие и не открывает настройки. При неизменном наборе установленных браузеров повторные нажатия ничего не исправят.

Источники: `Linklet/State/AppModel.swift:163`, `Linklet/UI/Preview/PreviewRootView.swift:238`.

Исправление: Choose browsers должно открывать раздел браузеров. В пустом состоянии показать «Все браузеры скрыты» и действие «Настроить браузеры». Не обязательно запрещать скрытие последнего браузера: важнее предоставить понятный выход.

Критерий приёмки: скрыть все цели, открыть ссылку, одним действием перейти к настройке видимости и восстановить Open in.

### 2. P1 — часть входящих ссылок молча теряется

**Подтверждено кодом.** handleIncoming получает массив URL, но выбирает только первый подходящий через first(where:). Остальные игнорируются без сообщения. Особенно существенно для программы, назначенной системным обработчиком ссылок.

Источник: `Linklet/State/AppModel.swift:91`.

Исправление: определить поведение для пакета ссылок: очередь с количеством оставшихся или выбор действия для всего пакета. Сохранить каждую поддерживаемую ссылку до явной обработки пользователем.

Критерий приёмки: передать три HTTP(S)-ссылки одним вызовом; все три доступны пользователю.

### 3. P1 — название страницы подменяет видимый адрес

**Подтверждено кодом.** Если у страницы есть title, домен исчезает из основного интерфейса. URL остаётся только во всплывающей подсказке. Заголовок задаёт сама страница; он не подтверждает её происхождение. Для приложения, открывающего внешние ссылки, это ухудшает возможность проверить адрес перед вводом данных.

Источники: `Linklet/UI/Preview/PreviewRootView.swift:58`, `Linklet/UI/Preview/PreviewRootView.swift:96`.

Исправление: постоянно показывать домен отдельно от title; полный URL открывать по нажатию или сочетанию клавиш. Различать HTTP и HTTPS без создания ложного впечатления, что HTTPS гарантирует надёжность сайта.

Критерий приёмки: страницы с одинаковым title и разными доменами остаются визуально различимыми без наведения мыши.

### 4. P1 — передача внешних схем системе без собственной проверки намерения

**Подтверждено кодом; практическая эксплуатация не проверялась.** Любая навигация, кроме HTTP(S) и about, передаётся в NSWorkspace.shared.open. Нет различения пользовательского клика и автоматического перехода, проверки разрешённых схем или обработки отказа открытия.

Источник: `Linklet/UI/Preview/WebPreview.swift:109`.

Следствие: страница может попытаться вывести пользователя в другое приложение. Это не доказательство выполнения произвольного кода: результат зависит от схемы, установленного обработчика и защиты ОС.

Исправление: отдельная политика внешних протоколов; не открывать автоматически переходы без подтверждённого пользовательского действия, показывать приложение назначения при необходимости. Явно обработать неподдерживаемые схемы и неудачу открытия. Проверить разрешённый пользовательский mailto/tel-сценарий и автоматический переход тестовой страницы.

### 5. P2 — первый запуск не объясняет следующий шаг

**Подтверждено кодом; степень затруднения — UX-гипотеза.** На старте выполняется только refreshTargets; приложение является LSUIElement. Повторное открытие приложения также не показывает настройки. Человек может решить, что запуск не состоялся, если не заметит значок в строке меню.

Источники: `Linklet/App/AppDelegate.swift:7`, `Linklet/App/AppDelegate.swift:15`, `Linklet/Info.plist`.

Исправление: один короткий стартовый экран с объяснением роли Linklet, действием «Попробовать предпросмотр» и назначением обработчиком ссылок. При обычном повторном запуске без URL и без видимых окон открывать настройки; учитывать запуск при входе в систему, чтобы не показывать их каждый раз.

### 6. P2 — выбор основного браузера скрыт за сортировкой

**Подтверждено кодом.** preferredTarget всегда равен первому visibleTargets. При включённой сортировке это максимум накопленного числа запусков. При выключенной — порядок обнаружения, где профили Orion идут раньше обычных браузеров, затем сортировка по имени. Закрепить основной браузер явно нельзя. Список в настройках использует model.targets и не отражает сортировку model.visibleTargets.

Источники: `Linklet/State/AppModel.swift:63`, `Linklet/Services/BrowserDiscoveryService.swift:35`, `Linklet/UI/Settings/SettingsView.swift:136`.

Пользователь отключает «Sort browsers by usage», но не получает ручное управление. Кроме того, изменение частоты может изменить назначение привычного ⌘1.

Исправление: поле «Основной браузер» с явным выбором и отдельной опцией «Выбирать автоматически по частоте использования». Сортировку остальных целей отделить от основного действия. В списке показывать бейдж «Основной» и тот же порядок, что в предпросмотре.

### 7. P2 — автозапуск не различает ожидание разрешения и выключенное состояние

**Подтверждено кодом для ветки статуса.** Состояние SMAppService сводится к сравнению с enabled. Если после регистрации требуется одобрение в системных настройках, переключатель показывает выключенное состояние, а текст сообщает «Launch at login is turned off».

Источник: `Linklet/State/AppModel.swift:132`.

Apple отдельно определяет состояние requiresApproval и предоставляет переход к Login Items: [документация статусов](https://developer.apple.com/documentation/servicemanagement/smappservice/status-swift.enum), [SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice).

Исправление: показать «Требуется разрешение macOS» и «Открыть системные настройки». Обновлять системные статусы при возвращении в приложение. Сейчас обновление связано с refreshTargets, а не с активацией приложения.

### 8. P2 — недоступны явные навигация и повторная загрузка

**Подтверждено кодом.** В текущем toolbar нет кнопок назад, вперёд, обновления и поля адреса. Методы PreviewSession существуют, но из UI не вызываются. Жесты назад/вперёд включены в WebKit, однако они не заменяют обнаруживаемые действия для всех способов ввода. При ошибке отображается только OK, без «Повторить».

Источники: `Linklet/UI/Preview/PreviewRootView.swift:42`, `Linklet/UI/Preview/PreviewRootView.swift:54`, `Linklet/State/PreviewSession.swift:46`. README строка 11 обещает отсутствующие элементы.

Исправление: вернуть компактные назад/обновить, основные сочетания клавиш и доступ к адресу. Ошибку показывать в контексте страницы с повтором и открытием в браузере. Обновить README и скриншот. showsFullURL сейчас сохраняется и тестируется, но не используется интерфейсом.

### 9. P2 — два переключателя окна заставляют вычислять режим

**Подтверждённая структура, UX-гипотеза.** «Keep the preview visible when switching apps» и «Keep above other windows» звучат близко. Второй отключается и дополнительно тускнеет при выключении первого. Зависимость выражена отступом, но пользователю всё равно нужно понять комбинацию.

Источник: `Linklet/UI/Settings/SettingsView.swift:77`.

Предлагаю один выбор «При переключении приложений»: «Скрывать предпросмотр», «Оставлять окно открытым», «Держать поверх других окон». Под выбранным вариантом — короткий текст о результате. Текущий вариант с зависимыми переключателями технически корректен, но хуже объясняет три фактических режима.

### 10. P2 — приватность и перенос страницы не объяснены в продукте

**Подтверждено кодом и документацией.** Используется nonPersistent WebKit-хранилище и один повторно используемый WebView. Передаётся только URL, но в настройках нет объяснения, что авторизация, формы и позиция страницы не переходят в выбранный браузер. Закрытие окна не создаёт новую приватную сессию.

Источники: `Linklet/UI/Preview/WebPreview.swift:13`, `Linklet/Services/BrowserLaunchService.swift:35`, `Linklet/UI/Preview/PreviewWindowController.swift:133`, `README.md`, `docs/PRODUCT.md`.

Исправление: небольшой блок «Приватность»: «Предпросмотр использует отдельную временную сессию. В браузер передаётся только ссылка. Закрытие окна не очищает сессию; она завершается при выходе из Linklet». Для явного сброса предусмотреть действие очистки/новой сессии, если это входит в продуктовую политику.

### 11. P2 — сообщения удалены от действия и не подсказывают восстановление

**Подтверждено кодом.** Один statusMessage обслуживает настройки и ошибки запуска браузера. В настройках он показывается внизу вторичным цветом максимум в две строки. Нет различения успеха, ожидания и ошибки, привязки к полю и явного удаления устаревшего сообщения. Ошибка открытия браузера попадает в alert с заголовком «Couldn't open the page».

Источники: `Linklet/UI/Settings/SettingsView.swift:22`, `Linklet/State/AppModel.swift:104`, `Linklet/UI/Preview/PreviewRootView.swift:42`.

Исправление: статусы рядом с соответствующим действием, отдельные ошибки страницы и браузера, понятное действие восстановления. Успех может исчезать автоматически; ошибка должна оставаться доступной до исправления или закрытия пользователем.

## Дополнительные технические риски для проверки

- **Асинхронное закрытие нового предпросмотра.** Успешный callback openCurrentURL безусловно закрывает общее окно. Если во время запуска браузера приходит новая ссылка, callback старой операции может скрыть её. Источник: `AppModel.swift:107`. Проверить с задержанным mock запуска; привязать завершение к идентификатору исходной сессии. Пока это вывод из кода, а не воспроизведённая гонка.
- **Ошибка перехода может вернуть предыдущий URL.** navigationDidFail снимает isPreparingNewPage и синхронизируется с webView.url. Если WebKit сохранил адрес предыдущей страницы, пропадает адрес неудавшегося запроса, а Open in может отправить предыдущую страницу. Источник: `PreviewSession.swift:69`. Проверить последовательность A успешно → B недоступен → Open in; хранить адрес попытки отдельно.
- **Старый title при загрузке новой ссылки.** load меняет URL, но не сбрасывает pageTitle. До следующего обновления WebKit заголовок предыдущей страницы может оставаться видимым. Источник: `PreviewSession.swift:29`.
- **Закрытие окна не равно остановке активности страницы.** Вызывается только stopLoading при сохранении WebView. По [документации Apple](https://developer.apple.com/documentation/webkit/wkwebview/stoploading()) этот метод останавливает загрузку ресурсов. Он не является гарантией завершения JavaScript/медиа. Проверить воспроизведение и фоновые запросы после закрытия; выбрать политику жизненного цикла.
- **Esc перехватывается раньше веб-страницы.** PreviewPanel закрывает окно на каждый Esc без модификаторов. Это конфликтует с закрытием модальных окон сайта и выходом из fullscreen. Источник: `PreviewWindowController.swift:21`. Проверить приоритет обработчиков в живом UI.
- **Длинный список выбора браузера не имеет ScrollView.** BrowserTargetPicker использует VStack фиксированной ширины 280 без ограничения высоты. Источник: `PreviewRootView.swift:299`. Проверить 20+ целей и длинные названия; добавить прокрутку с ограничением высоты.
- **Имена профилей Orion разбираются по последнему разделителю.** «Orion - Work - Client A» станет «Client A». Поиск «RC» по всему имени может ошибочно пометить профиль «Research» как Orion RC. Источник: `OrionProfileLocator.swift:39`, `:55`. Парсить префикс приложения, сохраняя полное имя профиля; канал определять по надёжным метаданным/корню.
- **Поиск браузеров синхронный на MainActor.** Запрос Launch Services, чтение bundle-метаданных и обход профилей выполняются из refreshTargets на UI-потоке. Это потенциальная задержка при большом числе приложений, а не измеренная проблема. Не обещать «лёгкость» и скорость без замеров.

## Понятность панели настроек

Что уже хорошо:

- Небольшое число секций, стандартные переключатели SwiftUI, прямое сохранение изменений без лишнего Save.
- Подписи объясняют результат большинства действий; зависимость настроек окна визуально обозначена.
- У браузеров есть иконки, имена, дополнительные подписи профилей, счётчик видимости.
- Статус системного обработчика сформулирован понятнее, чем название раздела.
- Можно попробовать предпросмотр до назначения Linklet обработчиком ссылок.

Что мешает:

| Сейчас | Почему требует размышления | Предлагаемая формулировка/структура |
| --- | --- | --- |
| Default link handler | Технический термин, тогда как кнопка говорит browser | «Открытие ссылок» / Open links with Linklet |
| Performance → Launch when I sign in | Автозапуск трудно искать в производительности | «Общие» → «Запускать при входе в систему» |
| Keeps the lightweight menu bar process ready… | Детали реализации вместо результата | «Linklet будет доступен сразу после входа в macOS» |
| Sort browsers by usage | Меняет одновременно порядок и основное действие | Отдельные «Основной браузер» и «Порядок остальных» |
| Shown browsers | Не уточняет, где они показываются; включает профили | «Браузеры и профили в меню “Открыть в…”» |
| Reset usage | Не объясняет последствие для основного браузера | «Сбросить статистику выбора» + пояснение результата |
| Open Test Preview — самая акцентная кнопка | Звучит как инструмент разработчика и конкурирует с настройкой | «Попробовать предпросмотр» при первом запуске; далее вторичное действие |
| targets available в меню | Внутреннее понятие; считает также скрытые цели | «Доступно для открытия: N» по видимым целям |

Русские варианты — примеры более ясных формулировок. Они не означают, что весь продукт обязан быть русским. Если аудитория русскоязычная, нужен полноценный перевод: в проекте сейчас нет соответствующих ресурсов локализации.

Предлагаемая последовательность на одной странице, без обязательной боковой навигации:

1. **Общие:** обработчик ссылок, краткое объяснение, статус, автозапуск.
2. **Предпросмотр:** один выбор поведения при переключении приложений.
3. **Браузеры и профили:** основной браузер, порядок остальных, видимость, обновление списка.
4. **Приватность:** временная сессия, что передаётся в браузер, когда очищаются данные.

При большом количестве браузеров ограничить высоту их списка, чтобы общие настройки не оказывались далеко внизу. Длинные пояснения и кнопку назначения обработчиком лучше не заставлять конкурировать в одной горизонтальной строке при минимальной ширине 640. Это рекомендации по структуре; реальное сжатие и контраст нужно подтвердить на экране.

## Архитектура и тесты

Сильные стороны: сервисы обнаружения, запуска и системного обработчика разделены; состояние UI централизовано; URL передаётся явному приложению; есть защита от передачи самому себе; данные предпросмотра отделены от обычных браузеров; иконки кэшируются; окно и WebView переиспользуются.

Все 7 тестов зелёные, но они проверяют ограниченный набор свойств: разрешённые схемы, нормализацию hostname, простое имя Orion, сохранение настроек, размер окна, немедленное обновление адреса. Это не покрывает полноценную маршрутизацию и UX.

При исправлениях приоритетны проверки: все цели скрыты; несколько входящих URL; стабильность основного браузера; requiresApproval; ошибка загрузки с сохранением адреса; новая ссылка во время запуска внешнего браузера; политика внешних схем. Для воспроизводимости этих сценариев AppModel стоит принимать сервисы через зависимости, как уже принимает UserDefaults.

## Очерёдность работ

1. Исправить потерю ссылок, тупик пустого списка, отображение домена и политику внешних схем.
2. Сделать явный выбор основного браузера, понятный первый запуск, состояния автозапуска и ошибки с восстановлением.
3. Упростить режим окна, перегруппировать настройки, объяснить приватность, синхронизировать документацию.
4. Провести живую проверку: светлая/тёмная тема, минимальное окно, длинные имена, 20+ целей, клавиатура, VoiceOver, fullscreen, несколько экранов, недоступная сеть, медленная страница, медиа после закрытия.
5. Дать 3–5 новым пользователям без подсказок попробовать приложение, закрепить браузер, изменить поведение окна, скрыть и восстановить браузер и объяснить, что переносится при Open in. Зафиксировать затруднения и время выполнения; пересмотреть экспертные оценки по результатам.
