# Передача Linklet 1.2 для подписи

Исходники подготовлены для **1.2 (сборка 3)**. База — опубликованный тег v0.1.1
(коммит 5541ef7) и текущая лента из коммита 62c6d98. Все изменения выпуска 0.1.1
сохранены, кроме явно изменённого поведения автоматического скачивания.

## Не менять

- `MARKETING_VERSION = 1.2`, `CURRENT_PROJECT_VERSION = 3` в Debug и Release.
- Bundle identifier: `Linklet`.
- Лента: `https://alybo.github.io/Linklet/appcast.xml`.
- Публичный ключ Sparkle из выпущенной 0.1.1:
  `se2KhBLlhCaMRw3PEox9XshU29f+wlHRQTXQsvgVAF8=`.
- Использовать соответствующий существующий закрытый ключ издателя в Keychain,
  account `app.linklet.sparkle`. **Новый ключ не генерировать.**
- Использовать ту же Apple Developer Team, которой подписана 0.1.1.
- `SUEnableAutomaticChecks = true`, `SUAutomaticallyUpdate = false`,
  `SUAllowsAutomaticUpdates = false`: в 1.2 скачивание только с подтверждением.

## Подготовка и публикация

1. Получить тег `v1.2`. Собрать именно его исходники. Тег не перемещать;
   если потребуется исправить код, согласовать новый тег/номер сборки.
2. Выполнить последовательные Xcode-тесты и `python3 -m unittest discover -s scripts/tests -v`.
3. Собрать Release для arm64 и x86_64, экспортировать с Developer ID,
   проверить подписи вложенного Sparkle, нотарифицировать и прикрепить ticket.
   Debug-entitlement `disable-library-validation` в релиз не включать.
4. Создать и подписать DMG; нотарифицировать и прикрепить ticket к финальному DMG.
5. Подготовить соответствующий полный архив исходников с зависимостями,
   точными версиями из Package.resolved и лицензиями, как описано в RELEASING.md.
6. Выполнить `scripts/prepare-sparkle-update.sh` с финальным DMG, архивом исходников
   и инструментами Sparkle. Скрипт ожидает build выше опубликованного 2,
   проверяет публичный ключ и режим обновлений, добавляет ченжлог из
   `Linklet/docs/releases/1.2.md` в описание и встраивает HTML-заметки
   `Linklet/docs/releases/1.2.html` в appcast.
7. В черновик GitHub Release `v1.2` загрузить ровно два файла:
   `Linklet-1.2.dmg` и `Linklet-1.2-source.tar.gz`. Заменить служебное описание
   черновика на подготовленный `release-description.md`, включающий ченжлог и SHA-256.
8. Проверить обновление **подписанной 0.1.1 (build 2) → подписанная 1.2 (build 3)**
   через отдельную тестовую ленту. Проверить скачивание, проверку подписи,
   установку, перезапуск, сохранение настроек браузеров и автоматических проверок.
   Для проверки использовать копию приложения; не изменять основную ленту до готовности.
9. Опубликовать Release с двумя файлами, проверить скачивание и только затем
   заменить `updates/appcast.xml` сгенерированной лентой, сохранив предыдущую запись.
   Дождаться успешного workflow Pages и проверить публичную ленту.

## Проверка на установленной 0.1.1

В 0.1.1 включены автоматическое скачивание и установка по умолчанию. Поэтому
переход на 1.2 может пройти автоматически согласно её сохранённым настройкам.
Правило «скачивать с подтверждением» вступает в силу уже в 1.2. Для ручного
контроля теста в 0.1.1 можно отключить автоскачивание и нажать «Проверить обновления».

До публикации подписанных файлов запись 1.2 в рабочую ленту не добавлять.
Черновик релиза сам по себе не запускает обновления. Неподписанные тестовые
сборки из локальной папки build не являются релизными файлами.
