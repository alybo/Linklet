# Linklet 1.7 (31): черновик для издателя

Владелец разрешил разместить 1.7 в GitHub Draft Release для подписи другом
с его Apple Developer аккаунта. Публичный выпуск и appcast здесь не создаются.

## Что передаётся

`Linklet-1.7-signing-kit.zip` содержит:

- `Linklet-1.7-31.xcarchive`: Release для arm64 и x86_64, внутри `Linklet.app`
  и соответствующие dSYM. Developer ID подписи и нотарификации нет.
- `Linklet-1.7-project.tar.gz`: только отслеживаемые исходники точного коммита,
  включая Package.resolved, инструкции и заметки. Это снимок проекта для
  обычной сборки через SwiftPM, а не финальный автономный corresponding-source.
- `FOR-PUBLISHER.md`, `DRAFT-HANDOFF.json`, `SHA256SUMS.txt`.

В комплект не включаются DerivedData, диагностические логи, пользовательские
данные, сертификаты, закрытые ключи или токены. Внешний SHA-256 — в описании
черновика. Владелец подтвердил, что сам протестировал сборку и всё работает;
повторять автоматические тесты издателю не нужно. Сборка 31 прошла
`xcodebuild build`. Полный прогон предыдущей сборки 27: 163 теста без ошибок.
Универсальная архивная сборка проверена отдельно; preflight ещё не выполнялся.

## На Mac издателя

1. Прочитать `RELEASING.md` и `Linklet/docs/RELEASE-AGENT-PROMPT.md`.
   Коммит точной передачи записан в `DRAFT-HANDOFF.json` и описании черновика.
   Сверить его с `origin/main`, версию 1.7 и build 31. При последующих исправлениях
   использовать новый согласованный коммит и возрастающий build.
2. Использовать существующий Developer ID Application из аккаунта издателя.
   Проверить согласованную Apple Team и Team предыдущего подписанного выпуска.
   Сохранить bundle identifier `Linklet`, текущий публичный ключ Sparkle и feed.
   Закрытый ключ Sparkle должен оставаться у издателя; заменять его нельзя.
3. На финальном коммите создать аннотированный тег `v1.7`, отправить его в origin;
   тег, HEAD и origin/main должны совпадать. Черновик уже существует: не создавать
   второй и не публиковать неподписанный комплект вручную.
4. Задать `LINKLET_SIGNING_IDENTITY`, `LINKLET_DEVELOPMENT_TEAM` и при необходимости
   `LINKLET_NOTARY_PROFILE` под существующие настройки издателя. Не записывать
   пароли, ключи или сертификаты в проект. Для этой передачи не создавать и
   не менять сертификаты, ключи или provisioning profiles вручную.
5. Выполнить `scripts/release-preflight.sh --owner-validated`, затем
   `scripts/publish-release.sh`. Не запускать preflight без этого флага:
   владелец явно попросил не повторять тесты после своей ручной проверки.
   Квитанция честно отмечает автоматические тесты как `skipped-owner-validated`,
   а не `passed`. Preflight сверит коммит, версию и тег, подготовит полный архив
   исходников и проверит его сборкой без тестов.
   Публикация заново соберёт universal app, подпишет Developer ID и Sparkle,
   нотарифицирует приложение и DMG, прикрепит tickets и проверит Gatekeeper.
   Архив в комплекте — передача на подпись, не замена квитанции preflight.
6. Скрипт заменит вложение черновика ровно двумя финальными файлами:
   `Linklet-1.7.dmg` и `Linklet-1.7-source.tar.gz`; опубликует appcast последним.
   Для новой minor-линии проверить реальное обновление подписанной 1.5 → 1.7.

Тег пока не создаётся, чтобы черновик можно было доработать до финальной проверки.
Предыдущий черновик 1.6 оставляется без изменений.
