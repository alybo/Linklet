# Промпт для нейронки, которая выпускает Linklet

Подготовь и опубликуй релиз macOS-приложения Linklet из репозитория
https://github.com/alybo/Linklet. Ты работаешь на Mac человека, который подписывает
приложение своим Developer ID и публикует GitHub Releases. Выполни весь процесс
на этом Mac: сборку, подпись Apple, нотарификацию, подпись Sparkle и публикацию.
Возвращать сборку владельцу проекта для дополнительной подписи не требуется.

Сначала прочитай RELEASING.md, Linklet/docs/SIGNING-HANDOFF.md и
Linklet/docs/UPDATES.md. Sparkle 2.9.6 уже подключён. Кнопка открытия в браузере
уже использует исходную ссылку; сохрани это поведение.

Вручную загружай в Assets ровно два файла: Linklet-VERSION.dmg и
Linklet-VERSION-source.tar.gz. ZIP приложения, SHA256SUMS.txt, appcast.xml и
release-description.md туда не загружай. Контрольные суммы включай в описание
релиза. Автоматические ссылки Source code от GitHub остаются как есть.

1. Получи актуальный main, сохрани чужие незакоммиченные изменения. Проверь
   существующие релизы, версию приложения, номер сборки и доступность Developer ID,
   нотарификации и GitHub. Используй настроенные учётные данные; не выводи в чат
   пароли, токены, закрытые ключи или содержимое файлов сертификатов.

2. Настрой ключ Sparkle ДО первой публичной сборки со Sparkle. Сейчас SUPublicEDKey
   в Linklet/Linklet/Info.plist содержит ключ с Mac владельца проекта. Для выпуска
   на этом Mac используй свой постоянный ключ. Инструменты находятся после
   разрешения зависимостей Xcode в
   SourcePackages/artifacts/sparkle/Sparkle/bin. Команда:

   ```sh
   /path/Sparkle/bin/generate_keys --account app.linklet.sparkle
   ```

   Она создаст ключ или использует существующий в Связке ключей этого Mac.
   Запиши полученную ПУБЛИЧНУЮ часть в SUPublicEDKey. Закрытая часть остаётся
   в Связке ключей; сообщи владельцу этого Mac о необходимости защищённой
   резервной копии. Новый ключ для каждого выпуска создавать нельзя.
   Если публичная версия со Sparkle уже существует, сначала выясни, какой ключ
   она использует: произвольная замена сломает проверку обновлений.

3. Установи следующую свободную версию MARKETING_VERSION и возрастающий
   CURRENT_PROJECT_VERSION, выше всех опубликованных сборок. Bundle identifier
   Linklet и согласованную Apple Developer Team сохраняй. Зафиксируй публичный
   ключ и версию в репозитории до окончательной сборки. Не перезаписывай старые
   теги или файлы релизов.

4. Разреши зафиксированные зависимости и проверь приложение:

   ```sh
   xcodebuild -project Linklet/Linklet.xcodeproj -scheme Linklet \
     -destination 'platform=macOS' -parallel-testing-enabled NO test
   ```

   Тесты запускай последовательно: существующие тесты языка используют общие
   настройки. Затем собери Release через Archive и экспорт Developer ID.
   Проверь Apple Silicon и Intel, если обе архитектуры заявлены в выпуске.
   Встроенные Sparkle и его вспомогательные приложения должны быть правильно
   подписаны при экспорте. Debug-entitlement disable-library-validation
   в релиз включать нельзя. Пройди нотарификацию Apple и прикрепи ticket.

5. Подготовь финальный DMG с приложением и ссылкой на /Applications. Подпиши
   и нотарифицируй сам DMG, прикрепи ticket. Все изменения образа нужно закончить
   до подписи Sparkle. Проверь подпись, Gatekeeper и stapling приложения и DMG.
   Подготовь полный архив соответствующих исходников с зависимостями и лицензиями
   согласно RELEASING.md; автоматический архив GitHub для этого недостаточен.
   Затем запусти:

   ```sh
   bash scripts/prepare-sparkle-update.sh /path/Linklet.dmg /path/Linklet-source.tar.gz /path/Sparkle/bin
   ```

   Скрипт использует account app.linklet.sparkle, создаёт файлы в build/sparkle/
   и готовит ссылки на GitHub Release с тегом vVERSION. Каталог release/ содержит
   два файла для Assets, feed/appcast.xml публикуется отдельно через Pages,
   release-description.md содержит текст для описания релиза с SHA-256.
   Проверь подпись Sparkle, номер сборки и ссылку на DMG в appcast.

6. Настрой GitHub Pages для репозитория: Settings → Pages → Source: GitHub Actions.
   Workflow .github/workflows/updates.yml уже подготовлен. Ожидаемый адрес:
   https://alybo.github.io/Linklet/appcast.xml. Убедись, что настройка не заменит
   существующий нужный сайт; при конфликте остановись и объясни его.

7. До выпуска проверь настоящее обновление между двумя подписанными сборками
   с тем же ключом, используя отдельную тестовую ленту. Проверь скачивание,
   проверку подписи, установку и перезапуск. Тестовую ленту и тестовые версии
   не публикуй в основном appcast. Если такую проверку выполнить не удалось,
   оставь релиз черновиком и явно сообщи, что осталось проверить.

8. Опубликуй согласованный тег vVERSION и GitHub Release с ДВУМЯ файлами из release/:
   DMG и архивом исходников. В описание включи текст release-description.md и
   изменения версии. Не загружай всю папку build/sparkle/ целиком или через wildcard.
   Проверь доступность скачивания. ПОСЛЕ ЭТОГО скопируй подготовленный appcast.xml
   в updates/appcast.xml, закоммить и отправь в main. Дождись успешного workflow
   Pages и проверь публичный appcast и его ссылки. Уже подписанный DMG не меняй.

9. В конце сообщи ссылку на релиз, commit/tag, версию и номер сборки, Team ID,
   архитектуры, SHA-256, адрес appcast и результаты тестов, нотарификации и
   реального обновления. Раздели выполненное и оставшиеся действия. При нехватке
   доступа попроси только конкретное недостающее действие у владельца этого Mac.
