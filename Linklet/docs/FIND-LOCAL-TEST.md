# Плавающий поиск на странице: локальная проверка

29 октября 2026. Локальная сборка без публикации и изменения версии.

## Поведение

- ⌘F открывает компактную панель справа под существующим заголовком, внутри области страницы. Заголовок, адрес, иконки и размеры WKWebView не меняются. Повторное ⌘F выделяет запрос для замены. Работает и физическая клавиша F при русской раскладке.
- Поиск без учёта регистра запускается через 120 мс после ввода. Показываются подсветка, номер и количество совпадений. Enter/Shift+Enter и стрелки переходят вперёд/назад с возвратом к началу/концу. Дополнительно работают ⌘G/⇧⌘G.
- Esc или крестик панели убирают поиск и подсветку, возвращая фокус странице. Окно не закрывается. Если редактируется адрес, первый Esc отменяет адрес; составление текста через IME сохраняет стандартную обработку отмены.
- У каждого основного и открытого сайтом окна свой запрос и свои результаты. При переходе страницы открытая панель сохраняет запрос и повторяет поиск после загрузки. Закрытие/замена сессии очищают состояние и отменяют ожидающий поиск.
- Текст поиска не сохраняется в UserDefaults, истории, общесистемном find pasteboard или recents NSSearchField. Поиск и подсветку выполняет WebKit; HTML и введённые пользователем значения не переписываются. Счётчик ограничен 10 000 совпадений: при достижении лимита явно показывает «10000+ совп.» вместо точного общего количества.

## API и ограничение совместимости

Публичный [WKWebView.find](https://developer.apple.com/documentation/webkit/wkwebview/find(_:configuration:completionhandler:)) возвращает в [WKFindResult](https://developer.apple.com/documentation/webkit/wkfindresult) только наличие совпадения. Для нативного подсчёта, текущего индекса и одновременной подсветки использован отдельный небольшой адаптер внутреннего WebKit API `_findString:options:maxCount:`, `_setFindDelegate:`, `_hideFindUI` и callback `_WKFindDelegate`. Такой путь используется и в исходниках [WebKit MiniBrowser](https://github.com/WebKit/WebKit/blob/main/Tools/MiniBrowser/mac/WK2BrowserWindowController.m).

Это SPI, а не гарантированный публичный контракт Apple. Перед использованием проверяется наличие всех трёх методов. Если их нет, поиск и переходы продолжают работать через публичный WKWebView.find: вместо выдуманного количества панель показывает «Найдено» или «0 из 0». Отдельный тест принудительно проверяет этот запасной путь. Изменение самой сигнатуры SPI в будущей системе потребует повторной проверки адаптера; перед релизом его нужно проверять на поддерживаемых версиях macOS. На минимальной macOS 14 эта сборка отдельно не запускалась.

## Автоматическая проверка

Обязательная команда:

```sh
xcodebuild -project Linklet/Linklet.xcodeproj -scheme Linklet -sdk macosx test CODE_SIGNING_ALLOWED=NO
```

Четыре интеграционных теста PageFindTests используют настоящие WKWebView/NSWindow и локальный HTTP-сервер:

1. Подсчёт пяти видимых совпадений: разные регистры, слово через inline HTML, фрейм с другого origin, совпадение ниже экрана. Скрытый текст исключается. Переходы в обе стороны и по кругу; неизменность HTML, поля формы и исходного URL; отсутствие совпадений; быстрая замена и очистка запроса; ограничение на 10 000 результатов.
2. Основное и всплывающее окно на минимальной ширине 640: настоящие клавиатурные события ⌘F, Enter, ⇧Enter, Esc, взаимодействие с ⌘L/адресом, фокус, независимость запросов, закрытие панели без закрытия окна, неизменность геометрии страницы. Снимки: `/tmp/linklet-find-main.png`, `/tmp/linklet-find-popup.png`.
3. Переход на другую страницу и назад с открытым поиском; отмена отложенного запроса при завершении сессии, отсутствие запоздалого восстановления состояния.
4. Принудительный отказ от SPI: публичный поиск, переход назад, наличие/отсутствие результата, отсутствие ложного счётчика.

Полный прогон: **122 теста, 0 ошибок**, `TEST SUCCEEDED`. Лог: `/tmp/linklet-find-full-tests.log`.

## Проверка владельцем

1. Завершить Linklet, распаковать `build/FindPreview/Linklet-Find-Test.zip` и заменить приложение в «Программах». Bundle ID остаётся `Linklet`, прежние настройки доступны. Готовая распакованная копия для быстрого теста: `/private/tmp/Linklet-Find-30b4b63/Linklet.app`. Тестовый XCTest bundle исключён; локальная ad-hoc подпись проверена через `codesign --verify --deep --strict`, в том числе после распаковки архива.
2. На длинной странице нажать ⌘F, ввести слово, проверить счётчик и подсветку. Перейти вперёд/назад стрелками и Enter/Shift+Enter. Повторное ⌘F выделяет запрос.
3. Проверить пустой запрос и запрос без совпадений. Нажать Esc в поиске, затем повторно открыть поиск; проверить крестик.
4. Открыть второе окно с сайта и проверить в обоих разные запросы. Перейти на другую страницу и назад с открытой панелью.
5. Проверить светлое/тёмное оформление, минимальную ширину, редактирование адреса при открытом поиске, поиск на собственных рабочих сайтах.

Релизная подпись/нотаризация и GitHub-публикация не выполнялись.

Архив упакован без resource forks и extended attributes. Файловый провайдер папки Documents повторно добавляет FinderInfo к вложенным bundles, поэтому проверяемая `.app` подготовлена в `/private/tmp`, а в проекте хранится переносимый ZIP.
