# Плавающий поиск на странице: локальная проверка

30 октября 2026. Локальная сборка без публикации и изменения версии.

## Поведение

- ⌘F открывает компактную панель справа под существующим заголовком, внутри области страницы. Заголовок, адрес, иконки и размеры WKWebView не меняются. Повторное ⌘F выделяет запрос для замены. Работает и физическая клавиша F при русской раскладке.
- Поиск без учёта регистра запускается через 120 мс после замены запроса; при дописывании/удалении суффикса задержка сокращается до 35 мс для плавного движения границы. Показываются подсветка, номер и количество совпадений. Enter/Shift+Enter и стрелки переходят вперёд/назад с возвратом к началу/концу. Дополнительно работают ⌘G/⇧⌘G.
- Esc или крестик панели убирают поиск и подсветку, возвращая фокус странице. Окно не закрывается. Если редактируется адрес, первый Esc отменяет адрес; составление текста через IME сохраняет стандартную обработку отмены.
- У каждого основного и открытого сайтом окна свой запрос и свои результаты. При переходе страницы открытая панель сохраняет запрос и повторяет поиск после загрузки. Закрытие/замена сессии очищают состояние и отменяют ожидающий поиск.
- Текст поиска не сохраняется в UserDefaults, истории, общесистемном find pasteboard или recents NSSearchField. Совпадения и прокрутку определяет WebKit; оформление текущего совпадения описано ниже. Текст страницы и значения полей формы не переписываются. Счётчик ограничен 10 000 совпадений: при достижении лимита явно показывает «10000+ совп.» вместо точного общего количества.

## Акцентная подсветка от 30 октября

- Текущее совпадение получает полупрозрачную заливку (24%) системного `NSColor.controlAccentColor`, две границы и круглые маркеры: начальный над строкой, конечный под строкой. Маркеры служат визуальному оформлению и не являются ручками редактирования.
- При дописывании/удалении суффикса того же слова левая граница остаётся на месте, правая и заливка меняются за 170 мс. Переход к другому результату или новому месту страницы не анимирует полёт между словами. Reduce Motion отключает движение. Смена системных цветов/оформления обновляет цвет без повторного поиска.
- WebKit по-прежнему выбирает настоящую DOM Range, считает совпадения, обходит фреймы и прокручивает страницу. Изолированный `WKContentWorld` читает эту Range, не подменяя поиск собственным поиском по текстовым узлам. У каждого фрейма свой renderer, поэтому для фреймов другого origin не требуются неточные пересчёты координат.
- Renderer добавляет один закрытый shadow-host к `document.documentElement`, а не оборачивает текст в span. Его `pointer-events:none` и `aria-hidden` сохраняют клики и доступность страницы. Временный adopted stylesheet подавляет стандартную заливку текущей DOM selection; при закрытии восстанавливается исходный набор стилей. Содержимое body и полей формы не переписывается.
- Scroll/resize, visual viewport, загрузка шрифтов и изменения DOM/размера обновляют геометрию через `requestAnimationFrame` только при активном выделении; постоянного таймера нет. При закрытии, отсутствии результата, навигации и pagehide слой скрывается, наблюдатели отключаются. Сообщения ready/gone содержат только идентификатор фрейма; сетевых запросов renderer не делает.
- WebKit рисует жёлтый ActiveTextMatch даже без ShowHighlight. После подтверждения доступной DOM Range штатная заливка убирается через уже использовавшийся `_hideFindUI`; приложение сохраняет индекс для последующих переходов. Круглые маркеры и акцентная заливка показаны у текущего результата. Если Range недоступна (например, некоторые поля/встроенные просмотрщики), остаётся штатное выделение WebKit. Публичный запасной поиск без SPI также сохраняет штатное оформление.

## API и ограничение совместимости

Публичный [WKWebView.find](https://developer.apple.com/documentation/webkit/wkwebview/find(_:configuration:completionhandler:)) возвращает в [WKFindResult](https://developer.apple.com/documentation/webkit/wkfindresult) только наличие совпадения. Для нативного подсчёта, текущего индекса и одновременной подсветки использован отдельный небольшой адаптер внутреннего WebKit API `_findString:options:maxCount:`, `_setFindDelegate:`, `_hideFindUI` и callback `_WKFindDelegate`. Такой путь используется и в исходниках [WebKit MiniBrowser](https://github.com/WebKit/WebKit/blob/main/Tools/MiniBrowser/mac/WK2BrowserWindowController.m).

Это SPI, а не гарантированный публичный контракт Apple. Перед использованием проверяется наличие всех трёх методов. Если их нет, поиск и переходы продолжают работать через публичный WKWebView.find: вместо выдуманного количества панель показывает «Найдено» или «0 из 0». Отдельный тест принудительно проверяет этот запасной путь. Изменение самой сигнатуры SPI в будущей системе потребует повторной проверки адаптера; перед релизом его нужно проверять на поддерживаемых версиях macOS. На минимальной macOS 14 эта сборка отдельно не запускалась.

## Автоматическая проверка

Обязательная команда:

```sh
xcodebuild -project Linklet/Linklet.xcodeproj -scheme Linklet -sdk macosx test CODE_SIGNING_ALLOWED=NO
```

Шесть интеграционных тестов PageFindTests используют настоящие WKWebView/NSWindow и локальный HTTP-сервер:

1. Подсчёт пяти видимых совпадений: разные регистры, слово через inline HTML, фрейм с другого origin, совпадение ниже экрана. Скрытый текст исключается. Переходы в обе стороны и по кругу; неизменность HTML, поля формы и исходного URL; отсутствие совпадений; быстрая замена и очистка запроса; ограничение на 10 000 результатов.
2. Основное и всплывающее окно на минимальной ширине 640: настоящие клавиатурные события ⌘F, Enter, ⇧Enter, Esc, взаимодействие с ⌘L/адресом, фокус, независимость запросов, закрытие панели без закрытия окна, неизменность геометрии страницы. Снимки: `/tmp/linklet-find-main.png`, `/tmp/linklet-find-popup.png`.
3. Переход на другую страницу и назад с открытым поиском; отмена отложенного запроса при завершении сессии, отсутствие запоздалого восстановления состояния.
4. Принудительный отказ от SPI: публичный поиск, переход назад, наличие/отсутствие результата, отсутствие ложного счётчика.
5. Акцентная подсветка на странице с CSP: настоящее дописывание кириллического слова, стабильная левая и движущаяся правая граница, анимация, системный цвет, Reduce Motion, прозрачность для кликов, прокрутка и очистка. Светлый и тёмный снимки: `/tmp/linklet-find-ios-light.png`, `/tmp/linklet-find-ios-style.png`.
6. Переход текущего выделения во фрейм другого origin: декорируется настоящая выбранная WebKit Range в локальных координатах фрейма.

Полный прогон: **124 теста, 0 ошибок**, `TEST SUCCEEDED`. Лог: `/tmp/linklet-find-accent-full-tests.log`.

## Проверка владельцем

1. Завершить Linklet, распаковать `build/FindAccentPreview/Linklet-Find-Accent-Test.zip` и заменить приложение в «Программах». Bundle ID остаётся `Linklet`, прежние настройки доступны. Готовая распакованная копия для быстрого теста: `/private/tmp/Linklet-Find-Accent/Linklet.app`. Тестовый XCTest bundle исключён; локальная ad-hoc подпись проверена через `codesign --verify --deep --strict`, в том числе после распаковки архива.
2. На длинной странице нажать ⌘F, ввести слово, проверить счётчик и подсветку. Перейти вперёд/назад стрелками и Enter/Shift+Enter. Повторное ⌘F выделяет запрос.
3. Проверить пустой запрос и запрос без совпадений. Нажать Esc в поиске, затем повторно открыть поиск; проверить крестик.
4. Открыть второе окно с сайта и проверить в обоих разные запросы. Перейти на другую страницу и назад с открытой панелью.
5. Проверить светлое/тёмное оформление, минимальную ширину, редактирование адреса при открытом поиске, поиск на собственных рабочих сайтах.

Релизная подпись/нотаризация и GitHub-публикация не выполнялись.

Архив упакован без resource forks и extended attributes. Файловый провайдер папки Documents повторно добавляет FinderInfo к вложенным bundles, поэтому проверяемая `.app` подготовлена в `/private/tmp`, а в проекте хранится переносимый ZIP.
