# Ошибки страниц и история посещений

30 октября 2026. Локальная сборка без изменения версии и публикации.

## Исправленная история

Ранее `PreviewWindowController.show` записывал входящий URL, `onPageFinished` обновлял его заголовок, а `LinkLibrary.recordOpening` вообще ничего не записывал при выключенной панели. Последующие переходы живого WKWebView не становились посещениями. Поэтому замечание владельца подтвердилось кодом.

Теперь запись происходит при committed-навигации главного документа и изменении адреса без перезагрузки (History API/hash). Заголовок обновляется отдельно; редиректы до commit, неудавшиеся попытки загрузки, iframe и загрузки файлов не становятся посещёнными страницами. История общая для обычных и открытых сайтом окон, независимо от видимости панели.

При закрытии в начало «Недавних» поднимается последняя действительно открытая страница окна, с её текущим заголовком и последней полученной позицией прокрутки. Исходный URL команды «Открыть в…» остаётся отдельным и не меняется при навигации. Открытие записи из истории использует фактический адрес этой записи.

Положение главного документа отслеживается через main-frame скрипт в отдельном WKContentWorld. Он передаёт только URL и координаты, без содержимого страницы, полей форм и cookies. Наблюдение scroll ограничено requestAnimationFrame; запись координат на диск объединяется с задержкой 500 мс и фиксируется при закрытии. При обычном выходе из приложения ожидающая запись координат всех окон также фиксируется сразу. URL/title сохраняются при посещении; последнее закрытие меняет порядок списка.

Существующая настройка сохранения между запусками остаётся единственным условием записи истории на диск. По умолчанию история живёт в памяти. Выключение сохранения удаляет данные с диска и отменяет ожидающую запись координат. Очистка/удаление записи не отменяются последующими scroll/close. Формат старой истории читается без поля position; закладки и настройки не сбрасываются. Лимит — 200 адресов.

## Границы восстановления места

Из «Недавних» восстанавливаются URL и координаты основной прокрутки. При недостаточной высоте страницы скрипт пробует восстановить место до 5 секунд, реагируя на изменение размеров документа. Колесо, нажатие клавиши или указателя прекращают восстановление, чтобы не спорить с пользователем.

Это не снимок живой вкладки: формы, POST body, внутренние scroll-контейнеры сайта, произвольное состояние JavaScript и авторизация в приватном store не восстанавливаются историей. Динамическая лента с изменившимся содержимым может показать другое содержимое на тех же координатах. Если сайт перенаправляет сохранённый URL, координаты к другому адресу не применяются.

## Ошибки и восстановление

- Сетевые ошибки показаны в содержимом окна: причина, адрес неудавшейся попытки и «Повторить». Различаются отсутствие/обрыв сети, timeout, недоступный адрес и TLS. Проверка сертификатов не обходится.
- При неудачном переходе A → B повтор обращается к B, а «Вернуться на страницу» показывает сохранённый живой документ A с его формами. Ошибка B не подменяет историю и не меняет исходную ссылку передачи в браузер.
- Отмена навигации, смена политики WebKit на скачивание и нормальные HTTP error documents (например, 403) не создают второй экран ошибки поверх сайта.
- Публичный [webViewWebContentProcessDidTerminate](https://developer.apple.com/documentation/webkit/wknavigationdelegate/webviewwebcontentprocessdidterminate(_:)) переводит окно в состояние сбоя. «Восстановить страницу» или ⌘R явно перезагружают текущий WKWebView; его окно, масштаб и исходный URL сохраняются. Автоматического цикла reload нет.
- Повтор committed POST явно обозначен как повторная отправка. Для неуспешного provisional POST без сохранённого тела запроса повтор отключён: нужно вернуться на сайт и отправить форму заново. История тела запросов не хранит.
- Поздние ошибки предыдущей WKNavigation и сообщения от отсоединённого WKWebView не должны менять состояние новой страницы.

## Проверки

```sh
xcodebuild -project Linklet/Linklet.xcodeproj -scheme Linklet -sdk macosx test CODE_SIGNING_ALLOWED=NO
```

**133 теста, 0 ошибок**, TEST SUCCEEDED. Лог: `/tmp/linklet-recovery-history-final-tests.log`. Локальная app и копия, распакованная из ZIP, прошли `codesign --verify --deep --strict`.

Новые сценарии используют локальный HTTP-сервер и настоящие NSWindow/WKWebView:

1. Миграция старых записей, сохранение координат, очистка, отмена ожидающей записи после выключения сохранения, лимит и независимость истории от sidebar.
2. HTTP redirect → фактическая страница → SPA URL/title → scroll → другое окно → закрытие исходного → последняя страница наверху → повторное открытие на сохранённых координатах → Back.
3. Разрыв соединения, правильный адрес ошибки, возврат к живой форме, реальная кнопка повторной загрузки, сохранение WKWebView/окна/истории/исходной ссылки.
4. Реальное завершение WebContent-процесса только собственного тестового WKWebView, публичный callback сбоя, независимость второго приватного окна и ручное восстановление. Test-only PID accessor WebKit используется только в XCTest bundle; в приложение он не включён. Запрошенное через `_killWebContentProcess` завершение в проверенном WebKit подавляет crash callback, поэтому для достоверного сценария завершается PID собственно тестового WebContent.
5. Отмена, 403 с документом сайта, классификация offline/TLS и запрет небезопасного повтора provisional POST.

Минимальная macOS 14 отдельно не проверялась. Тесты не используют реальные аккаунты и внешние сайты. Снимок ошибки: `/tmp/linklet-page-error.png`.

## Проверка владельцем

1. Полностью завершить текущий Linklet и запустить новую сборку.
2. Открыть сайт, перейти на другую страницу, прокрутить и закрыть окно. В «Недавних» последней должна быть конечная страница; при открытии возвращается её адрес и, если сайт позволяет, положение прокрутки.
3. Повторить на сайте с навигацией без перезагрузки. При выключенном сохранении между запусками история доступна только до выхода; при включённом — после перезапуска.
4. Из работающей страницы перейти на недоступный адрес. Проверить адрес в ошибке, «Вернуться на страницу», затем «Повторить» после восстановления доступности сайта.
5. Проверить несколько окон: ошибка одного не должна подменять интерфейс и историю другого. Проверить обычные скачивания и поиск.
