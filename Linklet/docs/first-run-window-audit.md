# Аудит первого запуска и окон Linklet 1.8

Проверен путь от запуска в чистом профиле до первого просмотра страницы. Для окон отдельно проверены открытие ссылки, фокус, наведение ещё до первого клика, переход указателя между сайтом и панелью, ввод в адрес и перетаскивание на странице.

| Наблюдение | Влияние | Решение в сборке 47 |
| --- | --- | --- |
| Команда закрытия использовала окно с клавиатурным фокусом. Кнопки были обычными SwiftUI-контролами. | В видимом фоновом окне первый клик мог уйти на активацию. Команда закрытия зависела от того, какое окно было ключевым в этот момент. | Нативные кнопки AppKit принимают первый клик. Закрытие адресуется окну кнопки, переходы идут через сессию страницы. |
| Проверка попадания курсора передавала координаты самого содержимого окна, хотя AppKit ожидает координаты его родительского представления. | При смещении представления область сайта и окно могли определяться неверно. Нативные курсоры также могли оставаться отключёнными после потери фокуса. | Используется правильная система координат. При потере фокуса системные курсоры возвращаются. Клики, движения и жесты сайта обрабатывает WebKit. |
| Окно предпросмотра сначала было прозрачным. Покрытие загрузки участвовало в обработке кликов. | Момент, когда окно показано системой, мог предшествовать готовности страницы принимать движения указателя. | Окно показывается сразу после размещения и компоновки. Покрытие загрузки пропускает указатель к странице. |
| Для нового сайта стандартный размер и центр экрана определялись разными путями. | На небольшом или дополнительном экране окно могло появиться далеко от указателя либо выйти за видимую область. | Новое окно размещается на экране под указателем, связанное — на экране исходного окна. Сохранённая геометрия сайта имеет приоритет и ограничивается видимой областью. |
| Знакомство дважды выполняло поиск установленных браузеров до показа окна. | Чтение сведений из установленных приложений могло задержать первый видимый экран. | Поиск выполняется в фоне после показа окна и переиспользуется настройками. |
| После «Начать» оставалось выбирать между настройками и быстрым поиском. Настройка браузера по умолчанию выглядела частью обязательного пути. | Пользователю сложнее сразу понять, что даёт Linklet и как попробовать его с текущим браузером. | «Открыть пример страницы» ведёт прямо в обычное окно. На финальном экране показано, где искать боковую панель. Назначение браузером по умолчанию явно описано как необязательное. |

Позиционирование продукта для первого экрана — компактное окно для ссылок рядом с текущей работой. Быстрый поиск, закладки, история и загрузки раскрывают этот сценарий после первого открытия. Назначение системным браузером имеет смысл предложить как способ автоматически направлять в Linklet ссылки из других приложений.

На указанном пине в чистом профиле движение мыши доходит до Pinterest. Поверх изображения сайт показывает окно входа, и указатель попадает в него. Поведение ленты после входа этим наблюдением не проверено. До первого клика, после закрытия панелей и в дочернем окне наведение проверено на локальной странице с CSS, событиями мыши и Pointer Events. Фоновое наведение зависит от штатной политики WebKit для окон без клавиатурного фокуса и системного режима полос прокрутки. Кнопки окна и наведение сайта проверяются отдельно.

В чистом профиле сборки 47 проверен путь «Пропустить» → «Начать» → «Открыть пример страницы», переход по ссылке на ней и возврат по ⌘[. В полном наборе 199 тестов, один пропущен, ошибок нет. Размещение при отключении физического второго монитора отдельно не проверялось.

Источники платформы: [первый клик AppKit](https://developer.apple.com/documentation/appkit/nsview/acceptsfirstmouse(for:)), [координаты hitTest](https://developer.apple.com/documentation/appkit/nsview/hittest(_:)), [подписка WebKit на движения указателя](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/mac/WebViewImpl.mm).
