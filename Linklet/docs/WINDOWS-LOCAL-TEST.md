# Единые веб-окна: локальная проверка

28 октября 2026. Первый этап браузерного плана; публикация на GitHub не выполняется.

## Что изменилось

- Обычные страницы и окна, создаваемые сайтами через JavaScript/POST, используют общую оболочку Linklet: верхнюю панель, фон, закругления, закрытие, back/forward, закладки, копирование и выбор браузера.
- Дочернее окно встраивает тот же WKWebView, который WebKit создал с переданной конфигурацией. Запрос не запускается второй раз; сохраняются opener, cookies, POST, история, postMessage и window.close(). В панели дочернего окна остаётся видимый домен сайта.
- В памяти есть общий наблюдаемый реестр обычных окон и всех вложенных веб-окон. Он отслеживает стабильные ID, заголовки, адреса, загрузку, фокус, минимизацию и связь с родителем. Переключение активирует живое окно, без загрузки URL заново.
- Это основа раздела «Открытые»; сам раздел в боковой панели будет следующим шагом.

## Сборка для владельца

Локальная Debug-сборка: `build/WindowPreview/Linklet.app` от корня репозитория.
Текущая тестовая копия использует исходный bundle ID `Linklet`, как установленное приложение: при замене `.app` она подхватывает прежние настройки. Перед заменой нужно завершить запущенный Linklet. Релизная подпись/нотаризация не выполнялись.

Первая выданная копия использовала отдельный ID `Linklet.WindowPreview` и название `Linklet Windows Test`. После её переноса в «Программы» настройки выглядели сброшенными, потому что macOS читала другой домен UserDefaults. Проверено, что исходный домен `Linklet` сохранился; переносить или перезаписывать настройки не потребовалось. Для последующих проверок с заменой установленной `.app` сохранять исходный ID, если владелец явно не попросил изолированный профиль.

Запуск первой упакованной `.app` дополнительно проверен через управление интерфейсом: открывается экран знакомства с общей оболочкой. Реальные пользовательские аккаунты при проверке не использовались. Вариант с исходным ID проверяется сборкой и метаданными, без запуска поверх текущей пользовательской сессии.

## Что проверить вручную

1. Открыть сайт, где раньше появлялось маленькое браузерное окно. Запустить то же действие: внешний вид нового окна должен совпасть с Linklet, с закладкой, копированием и выбором браузера вверху.
2. Пройти вход через всплывающее окно: после подтверждения оно должно закрыться, а исходная страница — получить результат. Формы и cookies между родителем и его окном сохраняются.
3. Перейти по ссылке внутри дочернего окна и вернуться назад его кнопкой. Исходная страница должна остаться на месте.
4. Изменить размер окна до минимального, проверить длинный заголовок/URL и доступность кнопок.
5. Закрыть дочернее окно: исходная страница продолжает работать. Закрыть родителя: его зависимые окна тоже закрываются.

Команда «Открыть в…» по-прежнему передаёт исходную входящую ссылку, включая вызов из дочернего окна. Новых разрешений для passkeys эта работа не добавляет.

## Автоматическая проверка

Штатный `xcodebuild -project Linklet/Linklet.xcodeproj -scheme Linklet -sdk macosx test CODE_SIGNING_ALLOWED=NO` — **96 тестов, 0 ошибок**. Лог: `/tmp/linklet-unified-windows-final-tests.log`.

Существующие сценарии OAuth/POST/blank/postMessage/window.close/длинного URL сохранены. Новые проверки покрывают общую оболочку в настоящих NSWindow, вложенные окна, смену заголовка, активацию без потери JS-состояния, одинаковые URL в отдельных окнах, минимизацию и очистку реестра при закрытии. Снимок нативного дочернего окна: `/tmp/linklet-unified-popup.png`.

Исходники Raycast не менялись. Посторонние untracked-файлы, существовавшие до задачи, не входят в изменения.
