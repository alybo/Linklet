# Обновления Linklet: что нужно знать

Sparkle — встроенный механизм обновления. Он читает список версий в интернете,
скачивает выбранную версию и проверяет её подпись перед установкой.
Пользователь может проверить обновления через меню Linklet или управлять
автоматическими обновлениями в настройках. Новые установки ежедневно проверяют
обновления, скачивают их в фоне и устанавливают после завершения Linklet.
Обе автоматические функции можно отключить.

## Кто что делает

- Компаньон выполняет весь выпуск: собирает приложение, подписывает Developer ID,
  проходит нотарификацию Apple, подписывает готовый DMG ключом Sparkle и публикует
  DMG с архивом соответствующих исходников в GitHub Releases.
- Затем он обновляет `updates/appcast.xml`; GitHub Actions публикует список
  обновлений на GitHub Pages. Отдельный сервер не нужен.
- Владельцу проекта не требуется получать и передавать обратно каждую сборку.

## Что уже подготовлено

Подключён Sparkle 2.9.6. В меню и настройках есть проверка обновлений. Фоновая
проверка, скачивание и установка включены по умолчанию; сохранённый выбор
существующего пользователя не перезаписывается при запуске.
Номер сборки берётся из CURRENT_PROJECT_VERSION в Xcode; для каждого нового
выпуска его необходимо увеличивать. Версия берётся из MARKETING_VERSION.

Адрес списка: https://alybo.github.io/Linklet/appcast.xml.
Файл в репозитории: `updates/appcast.xml`. Сейчас он пуст: вымышленных выпусков нет.
Workflow `.github/workflows/updates.yml` публикует только папку `updates`.
Для публичных обновлений нужно активировать GitHub Pages и выпустить подписанную
сборку. Готовый [промпт для нейронки компаньона](RELEASE-AGENT-PROMPT.md) описывает
весь процесс.

## Однократная подготовка публикации

1. Компаньону создать свой ключ Sparkle по инструкции ниже. Заменить публичный
   ключ в Info.plist до первой публичной сборки со Sparkle, затем опубликовать
   проверенные изменения в репозитории.
2. В GitHub → Settings → Pages выбрать Source: GitHub Actions.
   Переключить именно верхний список Source, где стоит Deploy from a branch.
   Выбирать Branch: main или папку /docs не нужно. Предлагаемые шаблоны создания
   workflow также не нужны: наш файл уже в репозитории.
3. Открыть Actions → Publish update feed → Run workflow → main → Run workflow.
   Дождаться зелёной галочки и открыть https://alybo.github.io/Linklet/appcast.xml.
   XML в браузере означает, что публикация работает. До первого обновления список
   может быть пустым. Домен и платный GitHub Enterprise для этого не нужны.
4. Перед первым публичным выпуском проверить настоящее обновление между двумя
   подписанными и нотарифицированными сборками, включая перезапуск приложения.

## Ключ Sparkle

На Mac издателя создана отдельная запись в Связке ключей:
account `app.linklet.sparkle`, название `Private key for signing Sparkle updates`.
Она находится в связке `login` (вход) и хранится как пароль, а не как объект
категории «Ключи». Искать в «Все объекты» по слову Sparkle.
Закрытый ключ не записан в проект. Его публичная часть находится в Info.plist.

Если издатель меняется до первой публичной версии со Sparkle, новый издатель
создаёт отдельный ключ на своём Mac:

```sh
/path/Sparkle/bin/generate_keys --account app.linklet.sparkle
```

Он передаёт владельцу только напечатанный публичный ключ. Этим значением заменяют
`SUPublicEDKey` в Info.plist до сборки первого выпуска со Sparkle.
Одинаковое имя account на двух Mac само по себе не означает одинаковые ключи.

Компаньон сохраняет резервную копию своего закрытого ключа в защищённом месте.
Закрытый ключ не пересылается через чат и не публикуется в репозитории.
После первого публичного выпуска нельзя произвольно заменить публичный ключ:
следующие обновления должны проверяться ключом, встроенным в установленную версию.

## Каждый следующий выпуск

1. Установить новую версию и больший номер сборки, проверить тесты.
2. Компаньону взять согласованные исходники по [инструкции подписи](SIGNING-HANDOFF.md).
3. Собрать и нотарифицировать приложение, прикрепить ticket. Создать DMG с этим
   приложением и ссылкой на /Applications; подписать и нотарифицировать сам DMG,
   прикрепить его ticket. Подготовить полный архив соответствующих исходников.
4. На том же Mac подготовить два файла релиза и appcast:

   ```sh
   bash scripts/prepare-sparkle-update.sh /path/Linklet.dmg /path/Linklet-source.tar.gz /path/Sparkle/bin
   ```

   Инструменты Sparkle находятся в Xcode DerivedData:
   `SourcePackages/artifacts/sparkle/Sparkle/bin`. Скрипт проверяет DMG и приложение
   внутри него, подписывает обновление и готовит файлы в `build/sparkle/VERSION-BUILD/`.
   В `release/` лежат только DMG и source.tar.gz для загрузки в релиз. В `feed/`
   находится appcast.xml, а контрольные суммы — в тексте release-description.md.
   Полноту исходников нужно проверить до запуска: скрипт проверяет читаемость
   архива, но не может подтвердить, что из него воспроизводится сборка.
   Он ничего не публикует и не экспортирует закрытый ключ.
5. Проверить содержимое appcast и обновление со старой сборки. Создать GitHub
   Release с тегом `vVERSION`, загрузить только два файла из `release/`, вставить
   текст release-description.md в описание релиза и добавить изменения версии.
   Правила комплектации исходников — в [RELEASING.md](../../RELEASING.md).
6. После доступности обоих файлов скопировать `feed/appcast.xml` в `updates/appcast.xml`
   и опубликовать изменение. Список обновляется последним, чтобы пользователи
   не получили ссылку на ещё недоступный файл. Готовый DMG больше не менять.

Первую версию со Sparkle пользователи устанавливают вручную. Последующие
версии смогут приходить через встроенное обновление.
