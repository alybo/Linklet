# Linklet как основной браузер: технический аудит и план

Дата: 28 октября 2026. Проверенная ревизия: `aa8528a` (`main`), Linklet 1.5, build 20.

Перед коммитом документа main синхронизирован с `6c0b6ad`: этот удалённый коммит изменяет только `updates/appcast.xml`, исходники приложения остаются проверенной ревизии.

## Вывод

Linklet можно развивать в компактный основной браузер на существующем WebKit. Сейчас приложение спроектировано для краткого предпросмотра: смена приложения может завершить страницу, новая входящая ссылка заменяет сессию, а часть веб-окон получает отдельный упрощённый интерфейс. Для ежедневной работы недостаточно добавить адресное поле и кнопку скачивания: сначала нужны единое управление окнами и недеструктивная навигация.

Рекомендуемый первый результат — браузер с отдельными окнами и разделом «Открытые», без обязательного внедрения вкладок. Существующие поиск, закладки, cookies, блокировщик и обновления дают полезную основу. Полную совместимость с Safari/Chrome, расширениями и всеми способами входа текущая сборка не обеспечивает.

Это аудит и план, без реализации функций. Приоритет P1 означает блокер для использования как основного браузера; P2 — следующую очередь. Некоторые пункты являются осознанным поведением предпросмотра, которое становится проблемой при смене роли продукта.

## Что проверено

- Архитектура приложения, входящие URL, жизненный цикл окон, WKNavigationDelegate/WKUIDelegate, адреса и история, боковая панель, хранение сайтов, блокировщик, метаданные приложения, тесты и конфигурация CI.
- Штатный `xcodebuild -project Linklet/Linklet.xcodeproj -scheme Linklet -sdk macosx test CODE_SIGNING_ALLOWED=NO`: **92 теста, 0 ошибок**, `TEST SUCCEEDED`. Лог: `/tmp/linklet-browser-audit-tests.log`. Сборка выполнялась установленным SDK macOS 27; минимальная версия проекта — macOS 14. Прогон не доказывает совместимость на macOS 14.
- Тесты уже проверяют реальные NSWindow/WKWebView, back/forward, private/persistent cookies, `window.opener`, `postMessage`, POST ровно один раз, `window.close()` и длинные OAuth URL. Эти сценарии нужно сохранить при переделке окон.
- Отдельная временная проверка текущего `URLPolicy` подтвердила принятие `https://` и `https:///missing-host` без hostname. Диагностический исходник/бинарник находятся в `/tmp/linklet-browser-audit-probe`, в проект не добавлены.
- Raycast: `npm test` — **3 теста, 0 ошибок**; `npm run typecheck` — успешно; `npm run build -- --output /tmp/linklet-browser-audit-raycast-build` — успешно. Обычный `npm run build` не смог записать результат в установленное расширение вне разрешённой рабочей директории, поэтому использован штатный параметр `--output` с каталогом в `/tmp`. `npm run lint:source` дважды не завершался в течение нескольких минут и был остановлен: проверка стиля **не подтверждена**, причину нужно установить отдельно. Исходники Raycast не изменялись.
- Поведение API сверено с документацией Apple, ссылки приведены рядом с выводами.
- Ручная проверка полного браузерного маршрута на реальных аккаунтах, signed Release, нескольких версиях macOS, видеозвонков, DRM и password managers не проводилась. Где поведение выведено из кода, это указано отдельно от воспроизведённых проверок.

Первый запуск тестов внутри файловой песочницы не получил доступ к кэшам Xcode. Повторный штатный прогон с разрешённым доступом завершился успешно. В логе есть системные предупреждения CoreSimulator/WebKit; падений тестов нет.

## Основные находки

### B01 · P1 · Два разных интерфейса веб-окон

**Подтверждено кодом.** `WebPreview.swift:122–161` отправляет обычный `target=_blank` GET без размеров в текущее окно. Скриптовые окна, POST и окна с заданными координатами/размерами идут в `WebPopupWindowController`. Поэтому дело не только в настройке «Открывать ссылки в новых окнах»: она управляет другим маршрутом, входящими ссылками приложения.

`WebPopupWindowController.swift:22–75` создаёт обычный NSWindow с адресом-меткой и кнопкой «Продолжить в браузере», без основной оболочки Linklet, навигационных кнопок и закладок. Скриптовый переход обычного сайта тоже может попасть сюда: эвристика не доказывает, что это окно входа.

**Решение:** общая оболочка окна для обычной страницы и дочернего веб-окна; возможность принять уже созданный WKWebView. Сохранить переданную WebKit конфигурацию, websiteDataStore, opener, POST и обработку закрытия. Apple требует создать возвращаемый WKWebView с предоставленной конфигурацией и сама загружает запрос — повторно загружать его нельзя. [Документация Apple](https://developer.apple.com/documentation/webkit/wkuidelegate/webview(_:createwebviewwith:for:windowfeatures:)).

**Приёмка:** target blank, обычный `window.open`, отложенный переход из `about:blank`, POST login, postMessage, вложенное окно и `window.close()` имеют согласованный интерфейс и сохраняют веб-семантику. Обычный клик, ⌘-клик и средняя кнопка маршрутизируются по явно заданным правилам.

### B02 · P1 · Нет редактора адреса; существующая заготовка разрушает историю

**Подтверждено кодом и пробой URLPolicy.** `PreviewRootView.swift:64–89` отображает заголовок, но не адресное поле. `PreviewSession.swift:174–179` содержит не подключённый `submitAddress()`. Он вызывает `load()`, которая отвязывает WKWebView, обнуляет back/forward и меняет `navigationID` (`:110–134`); SwiftUI создаёт новый WKWebView (`PreviewRootView.swift:94–95`). Прямое подключение метода к TextField даст сброс истории при каждом вводе адреса.

Кроме того, KVO-синхронизация пишет текущий URL в `addressText` (`PreviewSession.swift:244–246`), поэтому без отдельного черновика она сможет перезаписывать пользовательский ввод. `URLPolicy.canPreview` проверяет только схему; нормализатор принимает адреса без хоста. Более строгая основа URL/поиска уже есть в `SearchInput` (`Models/SearchEngine.swift:31–56`).

**Решение:** разделить начало сессии и переход внутри существующего WKWebView; отделить черновик адреса от фактического URL. ⌘L, Enter, Escape для отмены редактирования, вставка, URL/поисковый запрос, редиректы и выделение адреса. Поддержать hostname, localhost, IP, IPv6, порт, Unicode/IDN; отклонять некорректный адрес. Начальный входящий URL хранить отдельно и сохранять семантику существующей команды «Открыть в…» по AGENTS.md.

**Приёмка:** A → ввод B → Назад возвращает A; изменение URL/заголовка сайтом не стирает черновик. Повторный ввод и ошибка B не показывают адрес A как адрес попытки B.

### B03 · P1 · Нет собственной системы скачивания

**Подтверждено отсутствием реализации.** В координаторе нет WKDownloadDelegate, `shouldPerformDownload`, обработки `canShowMIMEType`, преобразования navigationAction/navigationResponse в download и выбора destination. Response-policy сейчас всегда возвращает `.allow` (`WebPreview.swift:234–241`). Это не обеспечивает надёжное скачивание attachment и недоступных для отображения форматов.

**Решение:** общий DownloadManager, `.download` для подходящих action/response, обработка Content-Disposition, destination, прогресс, отмена, ошибки, повтор/возобновление при наличии resume data, «Показать в Finder». Сохранять cookies и POST исходной WebKit-загрузки; независимый повтор через URLSession может потерять авторизацию. Не блокировать создание внутренних `blob:` загрузок правилом внешних входящих HTTP(S)-ссылок. Для файлов нужны безопасное имя, политика совпадений, проверка происхождения/quarantine и отсутствие автоматического запуска исполняемого файла. [WKDownload](https://developer.apple.com/documentation/webkit/wkdownload), [WKNavigationResponse](https://developer.apple.com/documentation/webkit/wknavigationresponse).

**Приёмка:** обычный файл, `download`-атрибут, attachment, POST export, файл за авторизацией, blob export, отмена, разрыв сети, одинаковые имена и закрытие исходного окна имеют определённый результат. Долгая загрузка не теряется молча при закрытии окна или выходе.

### B04 · P1 · Не реализован выбор файлов для загрузки на сайт

**Подтверждено кодом и документацией.** В единственном WKUIDelegate отсутствует `runOpenPanelWith`. Apple прямо указывает, что **на macOS без реализации этого метода file uploads по умолчанию отключены**. Это отдельная проблема от скачивания файлов. [Документация Apple](https://developer.apple.com/documentation/webkit/wkuidelegate/webview(_:runopenpanelwith:initiatedbyframe:completionhandler:)).

**Решение:** NSOpenPanel по параметрам WebKit, выбор одного/нескольких файлов и каталогов там, где это разрешено API, корректная отмена. Проверить file input, drag-and-drop вложений и отправку файлов в дочерних окнах.

### B05 · P1 · «Скрывать» завершает работу страницы

**Подтверждено кодом и существующим тестом `testHidingPreviewEndsTemporarySession`.** Потеря активности вызывает `previewApplicationDidHide()` (`AppDelegate.swift:17–23`), а тот закрывает окна (`AppModel.swift:301–305`). `previewDidEnd` завершает сессию; в приватном режиме очищаются данные. Даже при Keep open явное скрытие приложения через macOS попадает в закрытие из-за `NSApp.isHidden`.

Для краткого просмотра это существующий контракт. Для браузера переключение в редактор/менеджер паролей может лишить пользователя формы, звонка и страницы; скрытие должно оставлять сессию живой.

**Решение:** отделить видимость, минимизацию, деактивацию и закрытие. Для браузерного сценария предложить Keep open; сохранить отдельное явно описанное поведение краткого предпросмотра. Приватное хранение сайтов остаётся по умолчанию; оно не требует уничтожать живое окно при потере фокуса.

### B06 · P1 · Escape безусловно закрывает основное окно

**Подтверждено кодом.** `PreviewWindowController.swift:7–24` перехватывает Escape до передачи события WebKit. Страница не получает возможность закрыть свой диалог, обработать выход из fullscreen или отменить действие. Новый редактор адреса тоже должен получить приоритет.

**Решение:** цепочка обработки Escape: активный редактор/диалог → страница/fullscreen → остановка загрузки; закрытие браузерного окна — отдельной командой ⌘W. Существующее поведение предпросмотра можно оставить только в явно выбранном режиме.

### B07 · P1 · Потеря остальных URL во входящем пакете

**Подтверждено кодом.** `AppModel.swift:230–240` выбирает только первый search request или первый HTTP(S) URL. Остальные исчезают даже при включённых новых окнах. Поисковая команда также получает приоритет над обычными ссылками независимо от их положения.

**Решение:** обработать каждый допустимый элемент в исходном порядке; очередь на время выбора режима данных; согласовать новые окна и режим замены текущего предпросмотра. Браузерный путь не должен молча терять элементы.

### B08 · P1 · Недостаточная идентификация сайта и политика внешних схем

**Подтверждено кодом; эксплуатация не проверялась.** Основная панель показывает произвольный title сайта; фактический URL доступен в tooltip и копировании (`PreviewRootView.swift:68–73`). Постоянного видимого origin и состояния HTTP/HTTPS нет. В `WebPreview.swift:226–230` любая схема кроме HTTP(S)/about и внутренней welcome-команды автоматически передаётся в NSWorkspace — без проверки главного frame, прямого действия пользователя и согласия на запуск приложения.

**Решение:** видимый фактический домен и протокол, понятное состояние небезопасного HTTP/ошибки TLS, обработка userinfo/IDN. Выделить политику внешних приложений: main frame, контекст инициатора, пользовательское действие или подтверждение для скриптов/редиректов, запрет неожиданных локальных/служебных схем, понятный отказ. Не отключать проверку сертификатов ради совместимости. Отдельно обрабатывать внутренние blank/blob сценарии.

Автоматическое открытие JS-окон включено (`WebPreview.swift:12`), лимит 8 действует на один координатор (`:139`), а у каждого дочернего окна собственный координатор. Нужен также общий контроль всплывающих окон, не ломающий легитимные асинхронные OAuth-переходы.

### B09 · P1 · Разрозненное состояние окон и настроек

**Подтверждено архитектурой; пользовательские расхождения требуют отдельного регрессионного теста.** Обычные окна — `childPreviewModels` в AppModel; дочерние веб-окна — словарь `popupWindows` в каждом координаторе. `allPreviewModels` приватен и не является Observable-реестром. Открытые popup не представлены в общем списке окон/сессий. Раздел «Открытые» нельзя достоверно построить из истории ссылок.

Каждое новое обычное окно создаёт целый AppModel и отдельный AdBlockService с собственным таймером/подготовкой (`AppModel.swift:504–530`, `:104–108`). Часть сервисов общая, часть настроек — независимые @Published-снимки одного UserDefaults. Например, изменение поведения окна root-модели не обновляет соответствующие свойства уже созданного child; его контроллер подписан на child.

**Решение:** общий coordinator/registry окон, единые наблюдаемые настройки и общий блокировщик; отдельное лёгкое состояние каждого окна. Регистрация/удаление обычных окон и всех popup по одному контракту.

### B10 · P1 · Повторное открытие и восстановление сессии отсутствуют

**Подтверждено кодом.** Оба контроллера ставят `isRestorable = false`. Нет session store и списка недавно закрытых окон. `applicationShouldHandleReopen` возвращает true без открытия/активации полезного окна, когда их нет (`AppDelegate.swift:38–43`). Welcome может закрыть все текущие страницы (`AppModel.showWelcome`).

**Решение:** создать новое пустое/стартовое окно по команде и Dock reopen; переоткрытие недавно закрытого окна в памяти. Восстановление после перезапуска — отдельная opt-in настройка с понятной политикой для приватных окон. Не обещать восстановление cookies, POST-форм и произвольного JS-состояния по одному списку URL.

### B11 · P1 · Вход на сайты и разрешения устройств не закрывают браузерные сценарии

**Подтверждено конфигурацией; реальные провайдеры требуют проверки.** В Info.plist отсутствуют NSCameraUsageDescription/NSMicrophoneUsageDescription; собственного управления разрешениями сайтов нет. Отсутствие delegate метода само по себе не означает отказ: для media capture WebKit по умолчанию возвращает `.prompt`. Но нужные purpose strings и разрешения signed приложения всё равно следует подготовить и проверить. [Media capture delegate](https://developer.apple.com/documentation/webkit/wkuidelegate/webview(_:requestmediacapturepermissionfor:initiatedbyframe:type:decisionhandler:)), [camera](https://developer.apple.com/documentation/bundleresources/information-property-list/nscamerausagedescription), [microphone](https://developer.apple.com/documentation/bundleresources/information-property-list/nsmicrophoneusagedescription).

В репозитории уже отмечено ограничение WebAuthn/passkeys на произвольных сайтах (`docs/PASSKEYS-HANDOFF.md`), соответствующего entitlement в конфигурации нет. Apple требует отдельное одобрение managed capability; заявку подаёт Account Holder организационной Apple Developer команды. Это внешняя зависимость, не исправление добавлением строки в plist. WKWebView обрабатывает WebAuthn через WebKit; переписывать стандарт через JS не требуется. [Требования Apple](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.web-browser.public-key-credential?changes=la), [Passkey use in web browsers](https://developer.apple.com/documentation/authenticationservices/passkey-use-in-web-browsers).

**Решение:** отдельный план capabilities и подписанной проверки: пароль, OAuth, passkey/QR/security key, разрешить/запретить камеру и микрофон, смена решения, видеозвонок, screen share, геолокация. Для последних двух сначала подтвердить доступные публичные API на поддерживаемых macOS. Имитация Safari User-Agent не гарантирует принятие embedded-браузера провайдером.

### B12 · P2 · Возможна гонка завершения внешнего открытия

**Риск из кода, отдельным delayed-launch тестом не воспроизведён.** Callback `openOriginalURL` безусловно закрывает текущее окно после успеха (`AppModel.swift:318–328`). Если до callback в этом окне уже открылась новая входящая ссылка, завершение старой операции закроет её. `previewRequestID` меняется, но нигде не проверяется.

**Решение:** связать результат с ID окна/сессии и поколением операции; старый callback не меняет состояние новой страницы. Внедрить протокол/closure запуска браузера для задержанных тестов.

### B13 · P2 · Неполное восстановление после ошибок

**Подтверждено отсутствием обработки, конкретные сбои не воспроизводились.** Нет `webViewWebContentProcessDidTerminate`. Ошибки страницы, запуска внешнего браузера и 403 используют общий alert; 403 не обязательно означает блокировку входа. `navigationDidFail` снимает preparing и берёт URL из WKWebView (`PreviewSession.swift:215–247`), поэтому адрес неудачной попытки следует хранить отдельно.

**Решение:** состояния загрузки/ошибки, сохранение адреса попытки, повтор/назад/открытие исходной ссылки, обработка аварии WebContent. Не выполнять бесконечный автоматический reload и не повторять POST без решения пользователя. Завершать ожидающие callback диалогов при закрытии окна; проверить несколько JS-диалогов. Alert/confirm реализованы, prompt — нет (`WebPreview.swift:176–195`).

## Другие пробелы для основного браузера

| Область | Текущее состояние | Следующий шаг |
| --- | --- | --- |
| Базовые команды | Back/forward и жесты есть; reload/stop есть в модели, но нет основных элементов/горячих клавиш | ⌘R, stop/reload, ⌘N, ⌘W, ⌘L, ⌘F, ⌘+/−/0, стандартные меню и выбор окна |
| Управление окном | Стандартные кнопки скрыты; в styleMask нет miniaturizable; отдельного управления minimization/fullscreen нет | Рабочие минимизация, масштабирование и fullscreen с доступной клавиатурой и VoiceOver |
| История | «Недавние» — до 200 входящих ссылок; запись зависит от включения sidebar (`LinkLibrary.swift:132`) | Отделить историю посещений от видимости панели; учитывать committed top-level навигации только по выбранной политике приватности |
| Приватные сессии | Каждое обычное приватное окно имеет свой nonPersistent store; popup использует store родителя | Сохранить текущую изоляцию; явно решить поведение новых окон одного сайта. Не объединять приватные stores случайно |
| Блокировщик | Есть общая для окна система правил, нет исключения для конкретного сайта; переключение пересоздаёт страницы | Исключения для сайта и согласованное состояние всех окон; избегать потери форм/истории при переключении |
| Производительность | Обнаружение браузеров синхронно вызывается из MainActor; чтение/запись JSON блокировщика тоже местами синхронные | Измерить задержки и вынести тяжёлый I/O. Сетевая загрузка фильтров уже nonisolated, конвертация — Task.detached; это сохранить |
| Ограничение ресурсов | Favicon получает Data целиком и лишь затем проверяет 512 KB (`FavoriteSiteIconService.swift:64–68`) | Ограничение тела во время чтения, отмена ненужных задач; замеры 1/10/30 окон, CPU/RSS/энергии и выгрузка фоновых страниц по политике |
| Защита хоста | ENABLE_APP_SANDBOX=NO; Debug отключает library validation; release script запрещает это в финальной сборке | Отдельно оценить sandbox основного приложения и доступ к файлам/приложениям. Отсутствие App Sandbox у хоста не означает отсутствие sandbox у процессов WebKit |
| Печать/сохранение | Собственных команд печати, PDF/page export и reader mode нет | Проверить встроенное поведение WebKit; добавить нужные команды после базовых сценариев |
| Расширения/пароли/медиа | Собственных расширений, менеджера паролей, sync/import и политики DRM в коде нет | Проверить системные password managers/autofill и набор нужных сайтов; отдельные исследования, без обещания совместимости расширений Chrome/Safari |

## Целевая архитектура

Не переписывать приложение целиком. Выполнить постепенное выделение из существующего AppModel:

1. **BrowserWindowCoordinator / WindowRegistry** — владеет контроллерами, открывает/активирует/закрывает окна, учитывает parent/child и создаёт опубликованный список для панели/Dock/меню.
2. **Состояние окна** — стабильный UUID, исходный URL, фактический URL, адрес попытки и черновик, заголовок, загрузка, ошибка, back/forward, режим данных и родитель. Идентификатор окна не меняется при навигации.
3. **Общие сервисы и настройки** — SiteDataService, SearchSettings, LinkLibrary, AdBlockService, обновления, обнаружение/запуск браузеров. Не создавать их полный набор на каждое окно.
4. **Единая оболочка** — отображает как новый WKWebView, так и WKWebView, созданный из переданной WebKit конфигурации. Её redraw и смена адреса не пересоздают живую страницу.
5. **NavigationPolicy / DownloadManager / SitePermissions** — отдельные правила навигации, скачивания и разрешений, проверяемые без реальных аккаунтов.

AppKit/WebKit-вызовы и обновления UI остаются на MainActor; тяжёлый файловый I/O, преобразование данных и сетевые задачи выполняются подходящими фоновыми сервисами. Само наличие `Task {}` внутри MainActor не переносит синхронную работу в фон.

## Раздел «Открытые»: предлагаемая спецификация

- Новый сворачиваемый раздел **«Открытые · N»**, по умолчанию перед закладками и недавними. Порядок разделов и раскрытие сохраняются с миграцией существующих настроек.
- Одна строка на **живое веб-окно**, UUID окна является ключом. Два окна с одинаковым URL остаются двумя строками.
- Строка: favicon, заголовок с fallback на домен, доступный фактический адрес, выделение активного окна, индикатор загрузки. Для дочернего окна — понятная отметка/связь с родителем; не определять «авторизацию» по догадке о URL.
- Клик активирует существующее окно, при необходимости разворачивает минимизированное и показывает скрытое. **Никакой повторной загрузки URL.** Формы, scroll position и история сохраняются.
- Кнопка закрытия и контекстное меню: активировать, закрыть, скопировать адрес, добавить закладку. Массовое закрытие можно добавить следующей итерацией.
- Список обновляется при создании, навигации, смене title, фокуса и закрытии. Стабильный порядок создания; переход фокуса меняет выделение, не переставляет строки под курсором.
- Учитывать обычные окна, дочерние WebKit-окна и вложенные popup; исключить Settings, поиск, саму панель и welcome. Скрытие/минимизация не удаляют запись, фактическое закрытие удаляет.
- Список существует в памяти независимо от сохранения истории/данных сайтов. Сохранение адресов открытых окон после перезапуска требует отдельного opt-in восстановления.
- Узкая панель, длинные заголовки, пустое состояние, клавиатурный выбор/активация/закрытие и VoiceOver входят в первую итерацию.

## Регрессионная матрица

1. **Окна:** входящие A/B/C одним пакетом; настройка новых окон; target blank; ⌘/middle-click; window.open с размерами и без; delayed blank; POST ровно один раз; вложенный popup; закрытие родителя/ребёнка; повторные URL; десятки окон.
2. **Состояние:** ввод адреса во время редиректа; навигация/back/forward/reload/stop; замена входящей ссылки; поздний callback старого открытия; title SPA; ошибка provisional navigation; WebContent termination.
3. **Панель:** все живые окна отражены, активное выделено; клик не грузит страницу заново; минимизированное восстанавливается; после close нет «призрака»; существующие bookmarks/recent, reorder и narrow layout сохранены.
4. **Файлы:** MIME/attachment/download/blob/POST/cookies; несколько загрузок; cancel/retry/resume; дубликат имени; недостаток места/нет доступа; закрытие окна/приложения; file input single/multiple/directory и drag-and-drop.
5. **Приватность:** cookie isolation обычных приватных окон и общий store opener/popup; закрытие одного не очищает другое; history/session persistence только по выбранной политике; очистка данных; отсутствие записи OAuth-токенов и секретов в логи.
6. **Совместимость signed Release:** обычный вход, OAuth, passkeys/QR/security key при наличии capability, autofill, платежное окно, видеозвонок/медиа/fullscreen, разрешения и отказ, HTTP/TLS и внешние схемы из iframe/redirect.
7. **Платформа:** минимальная поддерживаемая и актуальная macOS, Intel/Apple Silicon по доступности, несколько экранов/Spaces, Reduce Motion, VoiceOver/клавиатура, сон/пробуждение, offline/медленная сеть, ресурсы при 1/10/30 окнах.

Для следующих работ использовать локальный HTTP fixture и внедряемые сервисы вместо реальных аккаунтов там, где достаточно автоматизации. Signed возможности и реальные провайдеры требуют отдельной ручной приёмки.
