# Тестовый стеклянный вид боковой панели

29 октября 2026. Локальная сборка; публикация и версия приложения не меняются.

## Выбор вида

Настройки → Боковая панель → Вид боковой панели:

- **Чёрный** — прежний вариант, остаётся значением по умолчанию для существующих и новых профилей.
- **Стекло (тест)** — чёрная левая часть с переходом к прозрачной правой части и нативной стеклянной кромкой.

Меняется только фон. Используются тот же `SidebarContour`, размеры, плечи у края экрана, строки, иконки, отступы, обработчик изменения ширины и анимация открытия/закрытия. Оформление веб-окон не затронуто. Выбор хранится отдельно в `sidebarAppearance`; остальные настройки, порядок разделов и закладки не сбрасываются. Переключение применяется к уже созданной панели; повторный запуск не нужен.

## Нативная реализация

Первый вариант применял `glassEffect(.clear, in: SidebarContour)` ко всей поверхности. Пользовательская проверка показала, что фон справа выглядит матовым: детали обоев исчезают. Сравнение SwiftUI `.clear` и AppKit `NSGlassEffectView.style = .clear` на одной полосатой подложке подтвердило одинаковое размытие. Публичные API предлагают выбор материала, но не документируют отдельную настройку радиуса его размытия.

Исправленный вариант оставляет середину прозрачной. Нативный SwiftUI `glassEffect(.clear, in: SidebarContour)` находится в фоне и ограничен маской обводки исходного контура шириной 36 pt, с растушёвкой маски 6 pt. Итог обрезается тем же `SidebarContour`. При выключенном режиме стеклянного слоя нет. Чёрная заливка — обычный градиент: слева она непрозрачна, после 58% ширины начинает плавно исчезать и у правой границы становится прозрачной. Градиент привязан к текущей видимой ширине при раскрытии.

Детали подложки видны через прозрачную правую часть; системное преломление и размытие остаются на кромке. Через середину фон виден без искажения. На правой границе добавлена тонкая светлая линия с меняющейся вдоль высоты интенсивностью; она следует исходному контуру, не перехватывает мышь и скрыта от accessibility. Градиент её маски привязан к раскрытой ширине, а толщина учитывает display scale. Синий оттенок проверочной сцены возникает из-за подложки; он не задан в рабочем оформлении.

Важное ограничение: нативный Liquid Glass меняет оптику при потере активного вида окна. Публичные SwiftUI `appearsActive` и `materialActiveAppearance(.active)` проверены на стенде и не фиксируют поведение этого стекла при реальной деактивации приложения. Поэтому тестовый вид использует недокументированный getter AppKit `_hasActiveAppearance` только в подклассе окна боковой панели. При выбранном стекле он возвращает активное оформление, сохраняя системное преломление и блик; чёрный режим вызывает исходную реализацию `NSPanel`, сохранённую через Objective-C runtime. Глобальных swizzle нет. `isKeyWindow`, `isMainWindow`, обработка ввода, активация приложения и остальные окна не переопределяются. Обычное скрытие панели при уходе фокуса сохранено.

Это экспериментальная зависимость от внутреннего поведения AppKit, которую необходимо перепроверять при обновлении macOS. Если система перестанет использовать этот getter для стекла, фиксация вида может перестать действовать. Сам нативный эффект создаётся публичным API; захвата экрана и собственного шейдера фона нет. `blur(radius: 6)` растушёвывает только альфа-маску кромки, а не фон.

Материал доступен только на macOS 26+. На macOS 14/15 остаётся чёрный вариант и пояснение в настройках; минимальная версия приложения не повышается. При «Уменьшении прозрачности» используется непрозрачный чёрный фон, даже если выбран тестовый вариант. Сам выбор при этом не стирается; системная настройка не меняется приложением.

Документация Apple:

- [glassEffect(_:in:)](https://developer.apple.com/documentation/swiftui/view/glasseffect(_:in:)) — применение эффекта к своей форме.
- [Glass.clear](https://developer.apple.com/documentation/swiftui/glass/clear), [Glass](https://developer.apple.com/documentation/swiftui/glass), [NSGlassEffectView](https://developer.apple.com/documentation/appkit/nsglasseffectview) — публичные параметры материала.

## Проверка

Обязательный полный прогон:

```sh
xcodebuild -project Linklet/Linklet.xcodeproj -scheme Linklet -sdk macosx test CODE_SIGNING_ALLOWED=NO
```

Новые проверки покрывают чёрный вид по умолчанию, сохранение выбора и существующих настроек, неизвестное значение настройки, реальный NSSegmentedControl в настройках, переключение уже созданной панели без изменения размера, рендер непрозрачных вариантов и fallback для Reduce Transparency. Прежние проверки геометрии и анимации выполняются вместе с ними.

Добавлена проверка контраста чёрно-белых полос за прозрачной частью: выбранное стекло должно сохранять различимые детали, а чёрный вариант должен полностью скрывать подложку. Проверка берёт точки внутри поверхности, вдали от нативной кромки. Обычный `NSView.cacheDisplay` возвращает промежуточную карту нативного материала, поэтому проверять им оптику самой кромки нельзя.

Экранная проверка на отдельном стенде с полосами и текстом: SwiftUI и AppKit с материалом на всей поверхности дают матовый правый край; прозрачная середина с нативной кромкой сохраняет отчётливые полосы. Растушёвка маски убирает резкий внутренний стык. Повторная проверка выполняется на одиночной панели с контрастными наклонными полосами: у правой границы они загибаются, виден тонкий светлый контур. Исходный код поверхности и подкласса окна перенесён в стенд без данных приложения. Тестовый стенд не читает настройки и данные установленного приложения.

Добавлена интеграционная проверка фокуса: панель получает key status, затем передаёт его другому nonactivating panel с текстовым полем. Декоративный active appearance остаётся включённым, а реальный key/main status и редактор поля меняются штатно. Переключение на чёрный вид возвращает исходный getter AppKit. В этом тесте отключён только делегат автоматического скрытия, чтобы сравнить видимое окно после потери фокуса; штатное скрытие покрывается прежними тестами.

Полный прогон: **114 тестов, 0 ошибок**. Лог: `/tmp/linklet-sidebar-lens-focus-final-tests.log`. Снимки непрозрачных вариантов: `/tmp/linklet-sidebar-black.png`, `/tmp/linklet-sidebar-glass-reduced.png`. Ветка старых macOS защищена availability-проверками; фактический запуск сделан на текущей системе, а fallback дополнительно проверен явным входным значением Reduce Transparency.

В прогоне остаётся прежнее предупреждение SwiftUI о публикации состояния в тесте списка загрузок. Оно есть и в логе предыдущей сборки `/tmp/linklet-image-context-menu-tests.log`; новый переключатель вида этого предупреждения не выдаёт.

## Что проверить владельцу

1. После замены сборки убедиться, что прежний выбор вида и остальные настройки сохранены. В новом профиле панель по умолчанию чёрная.
2. Выбрать «Стекло (тест)» в настройках и открыть панель над разными окнами/обоями. Проверить чёрный левый край и различимые детали обоев/окон через правую часть. Узкая наружная кромка может размывать фон.
3. Изменить ширину, открыть/закрыть панель, переключиться между мониторами: контур и анимация должны оставаться прежними.
4. Проверить читаемость длинных названий, прокрутку, контекстные меню, изменение ширины и редактор закладок.
5. Сравнить кромку до и после ввода в редактор закладок и при переключении активности. Если панель скрылась при уходе фокуса, это прежнее поведение; повторное открытие без клика не должно менять оптику. На контрастной подложке у правой границы должны быть видны изгиб деталей и небольшой блик.
6. Вернуть «Чёрный»: прежний фон должен восстановиться. После перезапуска выбранный вид сохраняется.

Тестовая копия: `build/WindowPreview/Linklet.app`, bundle ID `Linklet`. Перед заменой полностью завершить установленный Linklet. Сборка для владельца не запускается автоматически поверх его текущей сессии.
